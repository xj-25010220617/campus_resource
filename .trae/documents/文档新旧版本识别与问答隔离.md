# 文档新旧版本识别与问答隔离（修订版）

## Context

当前知识库只按 MD5 精确去重（[oss.py](file:///d:/实验室204/校园虚拟资源管理/backend/utils/oss.py#L281-L293)）：

- 同名但内容有改动、或文件名不同但内容高度相似的新版文件，都会被当成**两篇毫无关系的新文档**；
- 新旧两版都完整索引进 Milvus，问答检索时**平等竞争**，reranker 只看语义相关度，没有新版权重（[rag.py](file:///d:/实验室204/校园虚拟资源管理/backend/utils/rag.py#L1661-L1780)）；
- 同一个问题可能同时召回旧版和新版分块，模型把两套矛盾内容拼在一起回答。

目标：新文件上传后**自动识别疑似新旧版本**，由**上传者确认**后把旧版标记为历史版本；确认后**问答检索立即隔离旧版**，列表默认隐藏旧版并可查看历史；只标记不删除，可回滚。

## 方案概览

1. **数据模型**：`KnowledgeDoc` 增加 `superseded_by` / `superseded_at`；新增 `DocVersionCandidate`（疑似版本关系，待确认/已确认/已拒绝）。
2. **识别**：新增 `apps/knowledge/versioning.py`；索引成功后由 `detect_version_task` 异步判定，命中只写**待确认候选**，不直接改旧版。
3. **确认**：新增候选列表 / 确认 / 拒绝接口；确认后才写 `superseded_by` 并建 `DocRelation(replaces)`。
4. **隔离**：确认后，在 `rag.authorized_knowledge_docs` 与 `data_query._visible_docs_qs` 过滤 `superseded_by__isnull=True`，覆盖全部问答检索路径。
5. **区分**：序列化器输出 `is_latest` / `superseded_by` / `superseded_at`；列表默认隐藏旧版，`include_superseded=1` 可查看。
6. **回滚**：`post_delete` 信号链式恢复（删新版→旧版自动恢复；删中间版→后继接管）。

不改 Milvus 数据：旧版向量仍在库中，但确认后 `candidate_ids` 阶段已排除，`filter_ids` 不会命中，无需重灌向量库。

明确取舍：**确认前旧版仍参与问答**（这是"先确认再生效"的代价）；只有确认后才隔离。

## 详细设计

### 1. 模型与迁移

`backend/apps/knowledge/models.py`：

`KnowledgeDoc`（`freshness_date` 之后）新增：

superseded_by = models.ForeignKey(

新增 `DocVersionCandidate`：

```python
class DocVersionCandidate(models.Model):
    STATUS_CHOICES = [('pending', '待确认'), ('confirmed', '已确认'), ('rejected', '已拒绝')]
    new_doc = models.ForeignKey(KnowledgeDoc, on_delete=models.CASCADE,
                                related_name='version_candidates', verbose_name='新上传文档')
    old_doc = models.ForeignKey(KnowledgeDoc, on_delete=models.CASCADE,
                                related_name='superseded_candidates', verbose_name='疑似旧版文档')
    confidence = models.FloatField(default=0.0, verbose_name='置信度(0-1)')
    signals = models.JSONField(default=dict, verbose_name='判定依据')
    reason = models.CharField(max_length=512, default='', verbose_name='判定说明')
    status = models.CharField(max_length=16, choices=STATUS_CHOICES, default='pending')
    decided_by = models.ForeignKey(settings.AUTH_USER_MODEL, null=True, blank=True,
                                   on_delete=models.SET_NULL, related_name='version_decisions')
    decided_at = models.DateTimeField(null=True, blank=True)
    created_at = models.DateTimeField(auto_now_add=True, db_index=True)
    class Meta:
        db_table = 'doc_version_candidate'
        constraints = [models.UniqueConstraint(fields=['new_doc', 'old_doc'], name='uq_version_candidate_pair')]
```

- 语义：`old.superseded_by = new` 表示 old 已被 new 替代；`superseded_by is null` 即"当前最新版"。
- 迁移：`backend/apps/knowledge/migrations/0013_knowledgedoc_versioning.py`。

### 2. 识别模块 `versioning.py`

新增 `backend/apps/knowledge/versioning.py`（纯函数 + 落库函数，便于单测）：

- **归一化**
  - `normalize_text(s)`：小写、去空白与标点。
  - `split_version_marker(filename_or_title)` → `(base, has_marker)`：剥离 `v2/ver3`、`第X版`、`修订版`、`终版/最终版`、`新版/旧版`、`副本`、`(1)`、末尾日期等，返回基名与是否含显式版本词。
- **采样**：`sample_text(chunks)` 取首 2、中 1、尾 2 块拼接，上限 2500 字；表格类（`file_type in xls/xlsx/csv` 或有 `table_schema`）额外拼入列名。正文总长 < 300 字不判版。
- **相似度**
  - `char_shingles(text, n=3)` → 3-gram 集合；`jaccard(a, b)` 精确计算；
  - `title_similarity` 用标准库 `difflib.SequenceMatcher`（对归一化标题）。
- **候选池**：同 `(college_id, department_id)`（含校级文档）或同 uploader，`status='indexed'`、`review_status='approved'`、`superseded_by is null`、排除自身，按 `-created_at` 取 200 篇 → 标题相似度排序取前 12 篇 → 加载各自采样块算 Jaccard。
- **判定矩阵**

| 条件 | 动作 |
| --- | --- |
| 显式版本词 + 基名相同/标题相似 ≥ 0.5，且 Jaccard ≥ 0.6 | 生成候选（confidence=0.95） |
| `file_name` 完全相同且 Jaccard ≥ 0.85 | 生成候选（confidence=0.9） |
| 同 `file_name` 且 0.5 ≤ Jaccard < 0.85 | LLM 复核，通过才生成候选 |
| Jaccard ≥ 0.65 且标题相似 ≥ 0.55（含年份/届差异） | LLM 复核，通过才生成候选 |
| Jaccard < 0.65 或标题相似 < 0.45 | 不生成候选 |

- **LLM 复核**：复用 `utils.llm.llm_client.chat`（`temperature=0.0, max_tokens=200`），输入两份文档标题、文件名、上传时间、`freshness_date` 与前 800 字采样；要求返回 `{"same_document": bool, "newer": "new"|"old", "confidence": "high"|"low"}`。仅 `same_document && confidence=="high"` 生成候选；**LLM 不可用/解析失败/低置信一律不生成候选**（宁漏判不误判）。
- **新旧方向**：两边都有 `freshness_date` 时以较大者为新；否则用 `created_at`。若上传的是旧内容（补传归档），候选方向取"上传文档为旧版、候选文档为新版"，`DocVersionCandidate` 的 `new_doc/old_doc` 按内容新旧赋值，确认时统一以 `old_doc` 被替代。
- **受众保护**：仅当"新版受众是旧版超集"才生成候选（同学院/同部门、或新版校级、或同一上传者）；否则只记录一条 `replaces` 关系（不生成候选、不替代），避免"旧校级公开→新版部门/私密"导致其他用户突然查不到资料。
- **候选落库** `create_candidate(...)`：`get_or_create(new_doc, old_doc)`，附带 `signals`（`filename_equal`、`title_similarity`、`jaccard`、`llm_verdict`）与中文 `reason` 供上传者判断；已存在 pending/confirmed 时跳过。

### 3. 确认 / 拒绝

- `versioning.confirm_candidate(candidate_id, user)`：权限为**新文档上传者本人或 super_admin**；`transaction.atomic()` 内按 id 顺序 `select_for_update` 两行 → 写 `old_doc.superseded_by = new_doc`、`superseded_at = now` → `DocRelation.objects.get_or_create(source_doc=new_doc, target_doc=old_doc, relation_type='replaces')` → 候选置 `confirmed`、记录 `decided_by/decided_at`。幂等：非 pending 直接返回当前状态。
- `versioning.reject_candidate(candidate_id, user)`：仅置 `rejected`，不改旧版。
- 候选只对新上传文档生成一次；若上传者不处理，旧版保持参与问答。

### 4. 触发时机

- `backend/apps/knowledge/tasks.py` 新增 `detect_version_task`（`@shared_task(bind=True, max_retries=1, default_retry_delay=120, ignore_result=True)`），模式对齐 `auto_link_relations_task`（[tasks.py](file:///d:/实验室204/校园虚拟资源管理/backend/apps/knowledge/tasks.py#L45-L74)）；失败只记日志。
- 在 `index_document_task` 成功收尾（保存 `status='indexed'` 之后，约 L272-281）用 `utils.celery_dispatcher.safe_delay` 派发；**索引失败/重试不触发**。
- 先审后索引天然满足：非超管新版 `pending` 期间不检测；审核通过并索引完成后才产生候选。

### 5. 检索隔离（确认后生效）

- `backend/utils/rag.py` `authorized_knowledge_docs`（L1028）加 `.filter(superseded_by__isnull=True)`。该函数被 `_apply_hard_filters`、关键词/分块/标签/标题兜底/穷举扩展/图片检索与最终 `_filter_by_permission` 全部复用，一处改动覆盖全链路。
- `backend/utils/data_query.py` `_visible_docs_qs`（L42）同样加过滤，保证表格问答（Text-to-SQL）不读旧版。
- `_published_docs_queryset`（L521，热门统计）不改，统计口径保留全部文档。

### 6. 接口与"清晰区分"

新增 `backend/apps/knowledge/version_views.py`（对齐 `review_views.py` 的组织方式）：

- `GET /api/knowledge/version-candidates/`：当前用户待确认候选（上传者为本人；super_admin 可看全部），返回 `id, new_doc_id/title, old_doc_id/title/file_name, confidence, reason, created_at`。
- `POST /api/knowledge/version-candidates/{id}/confirm/`：确认替代。
- `POST /api/knowledge/version-candidates/{id}/reject/`：拒绝替代。
- `backend/apps/knowledge/urls.py` 注册上述 3 条路由。

序列化与列表：

- `backend/apps/knowledge/serializers.py`（详情 L36-52、列表 L125-134）增加 `is_latest`、`superseded_by`、`superseded_by_title`、`superseded_at`。
- `backend/apps/knowledge/views.py` `KnowledgeDocFilter`（L74-132）增加 `is_latest` 布尔过滤；`KnowledgeDocListView` 默认仅返回 `is_latest=True`，显式传 `include_superseded=1`（或 `is_latest=false`）时包含历史版本，保证"列表默认折叠旧版"。
- 上传去重响应补齐版本信息：`UploadSTSView`（L1001-1006）与 `UploadCallbackView`（L1079-1089）命中重复时返回 `is_latest` 与 `latest_doc_id`（沿 `superseded_by` 链走到最新版），避免用户拿到旧 ID 误以为上传成功。

### 7. 删除回滚

- `backend/apps/knowledge/versioning.py` 定义 `@receiver(post_delete, sender=KnowledgeDoc)`，并在 `backend/apps/knowledge/apps.py` `ready()` 导入注册。
- 逻辑：删文档 X 时，`KnowledgeDoc.objects.filter(superseded_by=X).update(superseded_by=X.superseded_by)`、`superseded_at` 同步清空或继承——直接后继接管，支持"删中间版本不掉链"；`DocRelation` 随文档 CASCADE 自动清理。信号同时覆盖单条删除与批量删除。

## 边界与取舍

- **确认前不隔离**：按"先确认再生效"，上传者未处理时旧版继续参与问答；候选列表接口用于提醒。
- **年份/届别高相似**：不靠纯阈值直判，必须 LLM 复核；Prompt 明确"不同届/不同年份的名单不算版本"。
- **旧版仍可浏览**：列表默认隐藏，`include_superseded=1` 可查看并带"已被替代"标记；仅问答检索排除，必要时超管可手工清除 `superseded_by` 回滚。
- **不自动删除**：保留审计与文件本身，OSS 对象不清理。
- **存量文档**：本次不做全库重算，只对上线后的新上传生效。
- **历史版本问答**：默认不召回旧版；后续如需支持"上一版/往年"提问，可在 `_apply_hard_filters` 依意图放开过滤，作为独立迭代。
