# 代码修改记录 — 2026-10-25

> **需求**：关联文档功能不应让用户手动选择目标文档（用户不应看到别人创建的文档），改为 **AI 直接自动关联到对应文档**。
>   原方案是「前端展示 AI 推荐候选 → 用户勾选 → 逐条建边」，会暴露「用户可浏览范围内的他人文档」供挑选，不符合预期。
>   本需求下线手动建边与 AI 推荐两条接口，移除上传时的 `relations` 入参，改为上传成功后异步调用 AI 直接落成 `DocRelation` 边。
>   标签（Tag）功能与关联的「查询 / 删除」能力保持不变。无数据库结构变更（`doc_relation` 表继续使用）。
> **修改人**：userName

## 二、新增代码范围

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/views.py` | 🔧 新增 `_ai_auto_link_relations(doc, limit=100)`：候选池 = `_admin_scope_filter(上传者可浏览范围)` + `visibility='public'`，排除自身与已关联目标，按最近上传取前 100 条；LLM 按 ID 挑选相关项并给出关联类型，`DocRelation.objects.get_or_create(...)` **直接落边**，丢弃 LLM 编造/越权 ID 与自关联，返回新建边数；4 个上传视图在 `safe_delay(index_document_task, ...)` 后新增 `safe_delay(auto_link_relations_task, new_doc.id)` 触发自动关联 |

## 五、验证步骤

1. `python -m py_compile apps/knowledge/views.py apps/knowledge/tasks.py apps/knowledge/serializers.py apps/knowledge/urls.py apps/knowledge/chunked_views.py` 语法通过 ✅
2. 开发环境回归：
   - 上传文档后数秒内，`GET /docs/{id}/relations/` 出现 AI 自动生成的关联边，详情接口 `relations` 字段同步可见；
   - 候选池仅含上传者可浏览范围内的**公开**文档：私密/越权文档不会被 AI 关联，也不会暴露给用户；
   - 手动建边接口 `POST /docs/{id}/relations/create/` 与推荐接口 `POST /docs/{id}/relations/recommend/` 返回 404，上传传入 `relations` 入参被忽略；
   - 标签功能不受影响：上传 `tags` 打标、`GET /tags/`、`/docs/{id}/tags/`、删除关联/标签均正常；
   - 无相关公开文档或 LLM 暂不可用时，上传成功但 `relations` 为空，不影响上传主流程。
