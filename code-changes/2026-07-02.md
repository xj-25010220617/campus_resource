### 2.3 管理后台用户接口响应修复 (`apps/admin_panel`)

> **背景**：`POST /api/admin/users/` 成功创建用户后响应体缺少 `id`（以及 `role_display`、`college_name`、`is_active`、`date_joined`、`last_login`、`resource_count` 等），前端拿不到新建用户的 ID。
>
> **原因**：`UserCreateSerializer` 的 `Meta.fields` 没有 `id`；而 `ModelViewSet.create` 默认沿用当前 action 的序列化器做 `to_representation`，导致响应里只有创建序列化器声明的字段。
>
> **方案**：覆盖 `UserAdminViewSet.create` / `update` / `partial_update`，在保存后改用 `UserAdminSerializer` 重新序列化，字段与列表/详情保持一致。


| 文件                          | 说明                                                                                                                                                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `apps/admin_panel/views.py` | 修改。(1) 新增 `create()` 重写：保存后用 `UserAdminSerializer` 重新输出，状态码 201；(2) 新增 `update()` 与 `partial_update()` 重写：保存后用 `UserAdminSerializer` 重新输出，状态码 200；(3) 移除未使用的 `from rest_framework.decorators import action`。 |


### 2.4 上传日志统计接口修复 + 参数统一 (`apps/resources`)

> **背景**：`GET /api/resources/upload-log/stats/` 返回 500，`AttributeError: type object 'UploadLog' has no attribute 'FILE_TYPE_CHOICES'`。
>
> **原因**：`UploadLog` 模型只有 `STATUS_CHOICES`；`file_type` 是普通 CharField 没有 choices 列表，但 stats 按文件类型分组时引用了 `UploadLog.FILE_TYPE_CHOICES`。
>
> **方案**：改为 `queryset.values('file_type').annotate(count=Count('id'))` 动态聚合。同时统一 query 参数命名（见下），补全 `college_id` 过滤与 `group_by` 子集筛选，修复时区 aware datetime 警告。

| 参数 | 说明 | 示例 |

## 五、对外暴露的新能力

### 接口 1：手动触发 AI 日期提取

```
POST /api/knowledge/docs/{id}/extract-freshness/?async=true|false
Authorization: Bearer <jwt>
```

- 异步（默认）：返回 `202 {task_id, status, doc_id}`
- 同步（`?async=false`）：返回 `200 {freshness_date, confidence, source_excerpt, raw_response}`

权限：仅 `super_admin` / `admin` 可触发；`admin` 仅能触发自己上传的文档。

### 接口 2：上传时自动触发

`UploadCallbackView` 返回成功之前，自动调用 Celery 任务提取日期，写回 `freshness_date`。前端无感。

## 六、关键设计

1. **零阻塞主链路**：上传回调通过 `safe_delay` 触发 Celery；Celery 不可用时仅记日志，不影响上传。
2. **数据库零迁移**：复用已有字段。
3. **三入口殊途同归**：上传自动 / 手动异步 / 手动同步，最终都调用 `extract_freshness_for_doc(doc_id)`。
4. **LLM 严格约束**：Prompt 不允许猜测；未找到日期时返回 `null` + `confidence='none'`。
5. **日期硬校验**：限定 2000-2099 年范围 + 三种格式归一化（YYYY-MM-DD / YYYY/MM/DD / YYYY年M月D日）。

#### 接口：AI 智能问答（流式）

```
POST /api/chat/ask/
Authorization: Bearer <jwt>
Content-Type: application/json

{"question": "什么是进程调度？", "conversation_id": null}
```

返回 SSE 流（text/event-stream），事件类型：


| 事件名                 | 触发时机       | data 格式                                      |
| ------------------- | ---------- | -------------------------------------------- |
| `start`             | 流开始        | `{"conversation_id": 1, "message_id": 1}`    |

| `suggested`         | 流结束后       | `["问题1", "问题2", "问题3"]`                      |
| `references`        | 流结束后（普通用户） | `{"count": 3, "summary": "参考了3份文档"}`         |
| `references_detail` | 流结束后（管理员）  | `[{"doc_title": "...", "score": 0.85, ...}]` |
| `done`              | 流结束        | `{"message_id": 1}`                          |


### 10.6 完整调用链路

```
用户 POST /api/chat/ask/
  → AskSerializer 校验
  → 获取/新建 Conversation + ChatMessage(role=user)
  → rag.retrieve() 双路检索
  → rag.build_rag_prompt(question, results, history=history) 含多轮上下文
  → llm_client.chat_stream() 流式生成
  → StreamingHttpResponse + SSE 事件
  → 流结束后：保存回答到 ChatMessage + 生成相关推荐 + 发送引用事件
```
