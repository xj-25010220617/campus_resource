# 代码修改记录 — 2026-10-22

> **需求**：超管账号上传的 private（私密）文档，其他账号（其他超管、学院管理员、部门管理员）都能在列表查到
>   `created_at` 并预览/下载文件内容——这是越权泄露。
>   根因：浏览链路的 `_admin_scope_filter` 只按 `college_id/department_id/uploader_id`（文档归属）过滤，
>   完全不看 `visibility`；而超管上传时 `college_id/department_id` 均为 null（校级文档），命中 `SCHOOL_LEVEL`
>   子句后对 college_admin / dept_admin / admin 全部可见；AI 检索链路的 `authorized_knowledge_docs` 中
>   super_admin 分支也是「直接返回全部」，导致其他超管也能检索到。
>   本需求将「超管上传的 private 文档」改为仅该超管本人可见（浏览 + AI 检索两条链路一致）。
>   其他角色、其他 private 文档的既有逻辑不变。无数据库结构变更。
> **修改人**：userName

## 一、删除代码范围

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/views.py` | `_admin_scope_filter` 删除原 `if user.role == 'super_admin': return queryset`（超管直接返回全量的旧逻辑，改为排除其他超管上传的 private 文档） |
| `backend/utils/rag.py` | `authorized_knowledge_docs` 删除原 `if role == 'super_admin': return qs`（同上，超管分支改为排除其他超管上传的 private 文档） |

## 二、新增代码范围

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/views.py` | 🔧 `_admin_scope_filter` 新增 `super_private = Q(visibility='private', uploader__role='super_admin')`；super_admin 分支改为 `queryset.exclude(super_private & ~Q(uploader_id=user.id))`（仅该超管本人可见）；非超管分支在角色过滤前先 `queryset.exclude(super_private)`（超管私密文档对所有非超管一律不可见），并同步更新方法 docstring |
| `backend/utils/rag.py` | 🔧 `authorized_knowledge_docs` 新增同款 `super_private = Q(visibility='private', uploader__role='super_admin')`，super_admin 分支改为 `qs.exclude(super_private & ~Q(uploader_id=user_id))`，并同步更新 docstring（超管可查看全部，但其他超管上传的 private 除外） |
| `backend/apps/knowledge/tests.py` | 🔧 新增 `SuperAdminPrivateDocTests` 测试类（6 个用例）：超管本人可浏览/可检索、其他超管不可浏览/不可检索、学院管理员/部门管理员均不可浏览 |
