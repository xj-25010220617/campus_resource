# 变更线 D：补 `GET /api/faq/generation-logs/` 与 `GET /api/faq/generation-logs/{id}/` 两个管理接口

> **追加原因**：变更线 C 的 `FAQGenerateTriggerView` 返回里写了"可通过 GET `/api/faq/generation-logs/{id}/` 查看进度"，但**路由与视图当时并未实际落地**——前端问起时确认缺失。本变更线把这两条接口补齐，与 FAQGenerateTriggerView 的 message 文案对齐，让前端可以做"触发 → 轮询详情"完整闭环。

## D.一、删除代码范围

无。

## D.二、新增 / 改动代码范围

### D.2.1 序列化器（新增）

| 文件 | 说明 |
|------|------|
| `backend/apps/faq/serializers.py` | ① import 行追加 `FAQGenerationLog`；② 末尾新增 `FAQGenerationLogSerializer(ModelSerializer)`，字段：`id, status, total_questions, clusters_found, drafts_generated, error_message, started_at, completed_at`，外加一个 `duration_seconds` 计算字段（由 `completed_at - started_at` 推得，未完成时为 `null`） |

### D.2.2 视图（新增）

| 文件 | 说明 |
|------|------|
| `backend/apps/faq/views.py` | ① import 行追加 `FAQGenerationLog` 与 `FAQGenerationLogSerializer`；② 在 `FAQManageDeleteView` 与 `FAQGenerateTriggerView` 之间新增 `FAQGenerationLogListView(ListAPIView)` 与 `FAQGenerationLogDetailView(RetrieveAPIView)` 两个类，统一使用 `IsFAQAdmin` 权限（super_admin / college_admin / dept_admin / admin）。List 端支持 `?status=running|completed|failed` 过滤，按 `started_at` 倒序 |

### D.2.3 路由（新增）

| 文件 | 说明 |
|------|------|
| `backend/apps/faq/urls.py` | import 段追加 `FAQGenerationLogListView`、`FAQGenerationLogDetailView`；在 `faq/generate/` 之后注册两条路由：`path('faq/generation-logs/', FAQGenerationLogListView.as_view(), name='faq_generation_logs')`、`path('faq/generation-logs/<int:pk>/', FAQGenerationLogDetailView.as_view(), name='faq_generation_log_detail')` |

## D.三、数据库变更

无（仍复用已有的 `faq_generation_log` 表，未变更表结构）。

## D.四、Migration 文件

无。

## D.五、行为对比

|------|--------|--------|
