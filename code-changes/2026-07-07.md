> **需求**：修复 `POST /api/knowledge/docs/{id}/extract-freshness/` 等 Celery 异步接口在本地开发环境（未安装 `celery`）返回 500 的问题。引入 `utils.shared_task_compat` 兼容层，使 `@shared_task` 在缺包时自动降级为同步执行，视图层 / 上传链路不再因为缺 celery 而 500。

## 二、新增代码范围

### 2.1 utils 工具模块

| 文件 | 说明 |
|------|------|
| `backend/utils/shared_task_compat.py` | `@shared_task` 兼容层：有 celery 时透传 celery 原版装饰器；未安装 celery 时装饰后的函数保留 `.delay()` / `.apply_async()`，调用时同步执行并打 warning 日志。函数体里调用 `self.retry()` 等 celery 专属 API 时，降级模式下 `self=None` 会抛 `AttributeError`，会被精准捕获并转日志（业务异常透传） |

### 2.2 knowledge / faq 任务模块改造

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/tasks.py` | 顶层 `from celery import shared_task` 改为 `from utils.shared_task_compat import shared_task`；`django.utils.timezone` 改为函数体内懒加载（防御性，与 celery 无关） |
| `backend/apps/faq/tasks.py` | 同样替换为兼容层 `shared_task`；补上 `from django.conf import settings`（先前缺失，导致 `FAQ_DEDUP_THRESHOLD` 取值会 `NameError`） |

### 2.3 knowledge 视图文档同步

## 五、行为对比

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 本地（无 celery）调用 `extract-freshness` | **500**（import 阶段 `ModuleNotFoundError: No module named 'celery'`） | 视图走同步分支，返回 200 + `{freshness_date, confidence, source_excerpt, raw_response}` |
| 本地上传文件触发 `index_document_task` | **500**（`utils/crawler.py:419` 同步 import 炸） | 同步执行索引流程 |
| 装了 celery 的生产环境 | 正常工作 | 行为完全一致（装饰器直接是 celery 原版） |
| 业务异常（数据库 / Milvus 错误） | 透传 | 透传（兼容层不会吞业务异常） |
