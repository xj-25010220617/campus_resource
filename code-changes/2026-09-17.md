# 代码修改记录 — 2026-09-17

> **需求**：`/api/platform/stats/` 的 `avg_response_sec` 均值约 7.5s 偏大 —— 原口径统计的是整条回答的完整生成耗时（含全部 token 流式输出 + 答案生成完之后的「推荐问题」LLM 调用 + 引用/图片事件构建）。改为「思考时长」口径：用户发送问题 → AI 输出首字的等待时间（含意图解析 / 知识检索 / LLM 首 token）。**接口字段名、数据库字段名均不变。**

## 二、新增代码范围

### 2.1 思考时长口径落地（backend/apps/chat/views.py）

| 文件 | 说明 |
|------|------|
| `backend/apps/chat/views.py` | 🔧 AskView.post 入口新增计时起点 `t0 = time.time()`；`event_stream()` 内新增 `first_token_ts`，首个非空 token 到达时记录；finally 回填改为 `first_token_ts - t0`（思考时长），未收到任何 token（超时/异常/断连）回填 0，由统计端 `response_ms>0` 过滤排除 |
| `backend/apps/chat/views.py` | 🔧 语音通道 `generate()` 同步改口径：`first_ts` 在首个非空 chunk 到达时记录，成功/异常均回填 `first_ts - t0`，无首字回填 0 |

关键片段（主通道）：

```python
# 思考时长计时起点：用户发送问题 → AI 输出首字（含意图解析/知识检索/LLM 首 token 等待）
t0 = time.time()
...
for token in stream:
    if token:
        if first_token_ts is None:
            first_token_ts = time.time()  # 思考时长终点：首字到达
        ...
# finally:
if first_token_ts is not None:
    elapsed_ms = int((first_token_ts - t0) * 1000)
else:
    elapsed_ms = 0   # 未收到首字 → 0，被统计端 response_ms>0 过滤排除
```

## 五、API 变更

无新增/删除接口，无字段变更。仅 `/api/platform/stats/` 的 `avg_response_sec` 与管理端 `avg_response_ms` 的**统计口径**变化：由「平均响应时长（整条回答生成）」变为「平均思考时长（发送问题到 AI 输出首字）」，新提问的数值预期显著下降；**历史存量行仍为旧口径**，随时间自然稀释，如需立即生效可手动清零存量（`UPDATE chat_querylog SET response_ms = 0;`，会同时影响管理端历史均值，慎用）。
