## 二、新增代码范围

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/views.py` | `FileUploadView.post`（文件直传）：① 文件类型校验后、大小校验前，新增 **0 字节空文件校验**——`uploaded_file.size == 0` 时 `raise ValidationError({'file': '不能上传空文件（文件内容为空）'})`，返回 400；② `needs_ai` 分支内新增**无内容跳过 AI**——`extracted_text` 去除空白后为空且非图片（`ext not in IMAGE_FILE_TYPES`）时，`ai_result = None`，直接走降级（标题=文件名、描述/关键词为空），不再调用 `_ai_classify` |
| `backend/apps/knowledge/views.py` | `BatchFileUploadView.post`（批量上传）：① 单文件类型校验后、大小校验前，新增 **0 字节空文件校验**——`uploaded_file.size == 0` 时追加到 `failed_results`（单文件失败不影响其他文件）；② AI 生成前新增**无内容跳过 AI**——`extracted_text` 去除空白后为空且非图片时，`ai_result = None`，标题回落文件名、描述/关键词为空 |

> 根因（两处叠加）：
> 1. 此前只校验文件类型与大小上限，未校验**下限**，0 字节文件也能走完上传流程。
> 2. 更关键的是，`FileUploadView` / `BatchFileUploadView` 在「提取不到有效文本内容」时仍调用 `_ai_classify(title, '')`——LLM 没有内容可读，只能**仅凭文件名**编造标题/描述/关键词。
>
> 0 字节只是其中一种情形；「空 Word / 空 PDF / 空 Excel」等文件**有字节但解析不出文本**（`extracted_text` 为空或纯空白），第一轮只挡 0 字节没挡住这一类。本轮补上「无有效文本内容且非图片 → 跳过 AI」的通用判断后，两类都覆盖。

## 五、API 变更

无新增 / 删除接口。行为变化：

- `POST /api/knowledge/upload/file/`（直传）：
  - 0 字节空文件 → 返回 `400`，`file` 提示「不能上传空文件（文件内容为空）」。
  - 有字节但解析不出文本的文件（空 docx/pdf/xls 等）→ 正常入库，但**不再调用 AI**：`title`=文件名、`description`/`keywords` 为空（旧行为：AI 仅凭文件名乱填）。
- `POST /api/knowledge/upload/batch/`（批量）：
  - 0 字节空文件 → 进入 `failed` 列表（`error='不能上传空文件（文件内容为空）'`）。
  - 有字节但无文本内容的文件 → 正常入库，`title`=文件名、`description`/`keywords` 为空（不调 AI）。

> 正常非空文件、图片文件（走视觉模型）行为不变，AI 自动分类照常。

6. 批量上传混合文件（含空文件 + 空 docx + 正常文件 + 图片）→ 空文件进 `failed`，其余正常入库，无内容的文件不调 AI、正常文件/图片正常分类
