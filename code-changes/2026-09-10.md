## 二、新增代码范围

### 2.1 0 字节空文件直接报错（覆盖全部上传入口）

| 文件 | 上传入口 | 说明 |
|------|---------|------|
| `backend/apps/knowledge/serializers.py` | `POST /upload/file/`（直传） | `FileUploadSerializer.file` 增加 `error_messages={'empty': '不能上传空文件（文件内容为空）'}`——DRF `FileField` 默认 `allow_empty_file=False`，0 字节会在序列化层被拒，此处把默认英文替换为中文 |
| `backend/apps/knowledge/views.py` | `POST /upload/file/`（直传） | 文件类型校验后新增 `uploaded_file.size == 0` 时 `raise ValidationError({'file': '不能上传空文件（文件内容为空）'})` |
| `backend/apps/knowledge/views.py` | `POST /upload/batch/`（批量） | 单文件类型校验后新增 `uploaded_file.size == 0` 时追加到 `failed_results` |
| `backend/apps/knowledge/views.py` | `POST /upload/sts/`（STS 凭证） | `UploadSTSView.post` 新增 `file_size == 0` 时 `raise ValidationError({'file_size': '不能上传空文件（文件内容为空）'})` |
| `backend/apps/knowledge/views.py` | `POST /upload/callback/`（回调） | `UploadCallbackView.post` 新增 `file_size == 0` 时 `raise ValidationError({'file_size': '不能上传空文件（文件内容为空）'})` |
| `backend/apps/knowledge/chunked_views.py` | `POST /upload/chunk/init/`（分片初始化） | `ChunkUploadInitView.post` 新增 `file_size == 0` 时 `raise ValidationError({'file_size': '不能上传空文件（文件内容为空）'})` |

> 说明：`batch` / `sts` / `callback` / `chunk/init` 四条路径此前**完全不经过 DRF `FileField`**，`size`/`file_size` 只校验了上限、未校验下限。本次统一补齐「0 字节拒绝」，错误文案一致为中文「不能上传空文件（文件内容为空）」。

### 2.2 空文档拒绝（应含文本却提取不到内容）

| 文件 | 上传入口 | 说明 |
|------|---------|------|
| `backend/apps/knowledge/views.py` | `FileUploadView.post` | 文本提取后新增判断：`ext` 属于纯文本类（`txt/md/html/csv/json/xml/yaml/yml`）或文档类（`pdf/doc/docx/ppt/pptx/xls/xlsx`）且 `extracted_text` 去空白后为空时 `raise ValidationError({'file': '不能上传空文件（文件内容为空）'})`。**PDF 特判**：调用 `_pdf_has_content()` 若检测到图片（扫描件）则放行，否则拒绝 |
| `backend/apps/knowledge/views.py` | `BatchFileUploadView.post` | 纯文本类提取后新增判断：`ext` 属于纯文本类且 `extracted_text` 去空白后为空时追加到 `failed_results`（批量只提取纯文本，文档类不做此判断） |

> 新增辅助函数 `_pdf_has_content(file_bytes)`：用 PyMuPDF 打开 PDF，逐页检查是否有文本或图片，用于区分「空 PDF」（无文本无图片）与「扫描件 PDF」（无文字层但有图片），避免把扫描件误判为空文件拒绝。

### 2.3 无有效文本内容时跳过 AI（防止乱填信息）

| 文件 | 上传入口 | 说明 |
|------|---------|------|
| `backend/apps/knowledge/views.py` | `FileUploadView.post` | `needs_ai` 分支内：`extracted_text` 去空白后为空且非图片时 `ai_result = None`，走降级（标题=文件名、描述/关键词为空），不再调用 `_ai_classify` |
| `backend/apps/knowledge/views.py` | `BatchFileUploadView.post` | AI 生成前同样判断：无有效文本内容且非图片时 `ai_result = None`，标题回落文件名、描述/关键词为空 |

> 背景：音视频、压缩包、3D 模型、设计源文件等**本就提取不出文本**，但确是合法文件。此前仍调用 `_ai_classify(title, '')`，LLM 没有内容可读，只能**仅凭文件名**编造标题/描述/关键词。补此判断后，这类文件正常入库但不再乱填，由用户后续手动补信息。（应含文本类型已在 2.2 拒绝，不会走到这里。）

## 五、API 变更

无新增 / 删除接口。行为变化：

| 场景 | 接口 | 行为 |
|------|------|------|
| 0 字节文件 | 直传 / 批量 / STS / 回调 / 分片 init | 返回 400 或进 `failed` 列表，提示「不能上传空文件（文件内容为空）」 |
| 空文档（空 Word/PDF/Excel/纯文本，有字节但无正文） | `POST /upload/file/` | 返回 400「不能上传空文件（文件内容为空）」（PDF 扫描件除外） |
| 空纯文本（有字节但全空白） | `POST /upload/batch/` | 进 `failed` 列表 |
| 扫描件 PDF（无文字层但有图片） | `POST /upload/file/` | 正常上传（不被误判为空） |
| 音视频 / 压缩包 / 3D / 设计源文件 | 直传 / 批量 | 正常入库，但 `title`=文件名、`description`/`keywords` 为空（不再调 AI） |
| 正常非空文件 / 图片 | 直传 / 批量 | 行为不变，AI 自动分类照常 |

## 六、验证步骤

1. `python -m py_compile apps/knowledge/views.py apps/knowledge/serializers.py apps/knowledge/chunked_views.py` → 通过
2. 直传 0 字节 `.txt` → 返回 400「不能上传空文件（文件内容为空）」
3. 直传「空 Word（.docx，有字节无正文）」→ 返回 400「不能上传空文件（文件内容为空）」
4. 直传「空 PDF（无文本无图片）」→ 返回 400；直传「扫描件 PDF（图片、无文字层）」→ 正常上传
5. 直传「空 txt（只有空格/换行）」→ 返回 400
6. 批量上传（含空 txt + 正常文件）→ 空 txt 进 `failed`，正常文件正常入库
7. STS / 分片 init 传 `file_size=0` → 返回 400
8. 直传正常 `.docx` / `.pdf` / `.txt` → AI 自动分类照常
9. 直传音频/视频/压缩包 → 正常入库，`description`/`keywords` 为空（不调 AI），`title`=文件名
