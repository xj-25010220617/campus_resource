## 二、新增代码范围

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/views.py` | `FileUploadView.post`（文件直传）：在文件类型校验之后、大小校验之前，新增空文件校验——`uploaded_file.size == 0` 时 `raise ValidationError({'file': '不能上传空文件（文件内容为空）'})`，返回 400 |
| `backend/apps/knowledge/views.py` | `BatchFileUploadView.post`（批量上传）：单文件类型校验后、大小校验前，新增空文件校验——`uploaded_file.size == 0` 时追加到 `failed_results`（单文件失败不影响其他文件） |

> 根因：`FileUploadView` / `BatchFileUploadView` 此前只校验文件类型与大小上限，未校验下限（0 字节）。空文件读出的 `extracted_text` 为空，但 `needs_ai` 仍为 `True`（用户未提供 description/keywords/visibility），于是 `_ai_classify(title, '')` 仍被调用，LLM 仅凭文件名生成标题/描述/关键词，造成「空文件乱填信息」。

## 五、API 变更

无新增 / 删除接口。行为变化：

- `POST /api/knowledge/upload/file/`（直传）：上传 0 字节空文件时，由「正常入库 + AI 乱填信息」变为返回 `400`，`detail`/`file` 提示「不能上传空文件（文件内容为空）」。
- `POST /api/knowledge/upload/batch/`（批量）：0 字节空文件进入 `failed` 列表（`error='不能上传空文件（文件内容为空）'`），其余正常文件不受影响。

## 六、验证步骤

1. `python -m py_compile apps/knowledge/views.py` → 通过
2. 直传一个 0 字节 `.txt` 空文件 → 应返回 400「不能上传空文件（文件内容为空）」，且不创建文档记录、不调用 AI
3. 批量上传混合文件（含一个空文件 + 若干正常文件）→ 空文件进入 `failed` 列表，正常文件成功入库且 AI 分类正常
4. 直传正常非空文件 → 行为不变，AI 自动分类照常
