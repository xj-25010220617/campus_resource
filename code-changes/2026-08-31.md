## 五、API 变更

### 5.1 新增接口

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/api/admin/departments/` | 超级管理员 | 新建部门，请求体 `{name, parent?, sort_order?}`，返回 `201` 部门对象 |
| DELETE | `/api/admin/departments/{id}/` | 超级管理员 | 删除部门，级联删除下级部门，用户 `department` 置空，返回 `204` |

### 5.2 变更接口

| 方法 | 路径 | 变更 |
|------|------|------|
| GET | `/api/admin/departments/` | 行为不变（树形列表、所有管理员）；移除无效 `college_id` 过滤参数 |

### 5.3 请求 / 响应示例

```json
// POST /api/admin/departments/ 请求体
{ "name": "党委办公室", "parent": 1, "sort_order": 3 }

// 响应 201
{ "id": 14, "name": "党委办公室", "parent": 1, "sort_order": 3 }

// DELETE /api/admin/departments/14/ 响应 204
```

### 5.4 向后兼容

- GET 列表结构、权限、排序规则零变更
- POST / DELETE 为新增能力，旧前端无感知
- 删除部门后用户 `department_id` 置为 `NULL`（模型 `SET_NULL`），不删用户
