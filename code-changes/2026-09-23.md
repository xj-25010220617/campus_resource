# 代码修改记录 — 2026-09-23

> **需求**：服务器切换到 Milvus Lite 后向量库为空，需在自动部署流水线中"仅在 Milvus 为空时"自动重灌知识库，
>   避免每次部署都清库重建（重灌动作一次生效，后续部署自动跳过）。
>   无数据库结构变更。

## 二、新增代码范围

### 2.1 重索引脚本守卫 (backend/scripts/reindex_all.py)

| 文件 | 说明 |
|------|------|
| `backend/scripts/reindex_all.py` | 🔧 新增 `milvus_is_empty()`：连接 Milvus 后判断 collection 是否存在、`num_entities == 0`；判断过程异常时按空处理返回 True，交由后续 `rebuild_collection` 重连给出最终结论 |
| `backend/scripts/reindex_all.py` | 🔧 `__main__` 改用 `argparse` 新增 `--if-empty` 参数；开启时若 `milvus_is_empty()` 为 False 则打印跳过信息并 `sys.exit(0)`；`rebuild_collection()` 失败由原先静默返回改为 `sys.exit(1)`，使部署流水线能感知重建失败 |

### 2.2 部署流水线接入 (.github/workflows/deploy.yml)

| 文件 | 说明 |
|------|------|
| `.github/workflows/deploy.yml` | 🔧 `migrate` 之后由原先直接 `systemctl restart campus-backend` 改为「`systemctl stop` → `python scripts/reindex_all.py --if-empty` → `systemctl start`」：先停后端避免 reindex 与运行中后端并发访问 Milvus Lite 文件（嵌入式单进程不支持多进程并发），首次切换后自动灌库，后续部署因 `--if-empty` 直接跳过；reindex 失败用 `|| echo` 告警不阻断部署，保证后端必被重新启动 |

## 五、验证步骤

1. `python -m py_compile backend/scripts/reindex_all.py` 语法通过
2. `python scripts/reindex_all.py --if-empty`（本地连远程 MySQL + Milvus 为空时）应走「重建 → 逐篇重索引」；Milvus 已有向量时打印「已有向量数据，跳过重索引」并退出码 0
3. 不带 `--if-empty` 手动执行 `python scripts/reindex_all.py` 行为与改动前一致（无条件重建），回归通过
