## 二、新增代码范围

### 2.1 文件大小限制常量（backend/apps/knowledge/serializers.py）

| 类型 | 旧限制 | 新限制 |
|------|--------|--------|
| 图片（png/jpg/jpeg/gif/webp） | 10MB | **30MB** |
| Word（doc/docx） | 50MB | **30MB** |
| Excel（xls/xlsx） | 50MB | **30MB** |
| PPT（ppt/pptx） | 50MB | 50MB（不变） |
| PDF（pdf） | 50MB | 50MB（不变） |
| 压缩包（zip/rar） | 未定义（兜底 50MB） | **80MB**（新增独立档） |
| 文本（txt/md/html） | 50MB | 50MB（不变） |
| 音频（mp3/wav/ogg/flac/aac/m4a） | 50MB | 50MB（不变） |
| 视频（mp4/webm/mov/avi/mkv/flv） | 500MB | 500MB（不变） |
| 其他（other） | 50MB | 50MB（不变） |

### 2.2 直传 / 批量上传补大小校验（backend/apps/knowledge/views.py）

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/views.py` | 顶部从 `.serializers` 增导入 `FILE_SIZE_LIMITS` |
| `backend/apps/knowledge/views.py` | `FileUploadView.post`（文件直传）：文件类型校验后新增文件大小校验，超限 `raise ValidationError({'file': '...超过 X MB...'})` |
| `backend/apps/knowledge/views.py` | `BatchUploadView.post`（批量上传）：单文件类型校验后新增大小校验，超限追加到 `failed_results`（单文件失败不影响其他文件） |

> 此前直传 / 批量上传两条 multipart 路径只校验了文件类型、未校验大小，导致只有 STS 直传 / 回调路径受 `FILE_SIZE_LIMITS` 约束。本次补齐后四条上传路径一致。

### 2.3 部署配置（backend/deploy/nginx.conf）

| 文件 | 说明 |
|------|------|
| `backend/deploy/nginx.conf` | `/api/knowledge/upload/` 的 `client_max_body_size` 由 `100m` 调整为 `500m`，避免 Nginx 在业务校验之前拒绝大文件（视频 500MB） |

## 五、API 变更

无新增 / 删除接口。行为变化：

- `POST /api/knowledge/upload/file/`（直传）与 `POST /api/knowledge/upload/batch/`（批量）现在会按类型拒绝超限文件，返回 400（直传）或进入 `failed` 列表（批量）。
- 各类型大小限制变化见 2.1 表（图片 10→30MB、Word/Excel 50→30MB、压缩包新增 80MB 档）。

## 六、验证步骤

1. `python manage.py check` → 0 问题
2. 直传一个 25MB 的 JPG 图片 → 应成功（旧 10MB 会拒绝）
3. 直传一个 40MB 的 Word → 应返回 400「docx 文件大小不能超过 30MB」
4. 直传一个 60MB 的 zip → 应成功（80MB 档）
5. 批量上传混合文件（含超限文件）→ 超限文件进入 `failed` 列表，其余正常
