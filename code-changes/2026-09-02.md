## 附：需求二 — 文件扩展名映射到类别（mp4/avi/mkv → video）

> **需求**：前端要求后端将 mp4/avi/mkv 等扩展名统一映射到 `file_type` 的「video」类别，并一并补全 audio/image 等全部扩展名 → 类别的映射。
> **修改人**：Fressia-zzt

### 删除代码范围

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/chunked_views.py` | 删除本地 `_FILE_TYPE_MAP` 常量（仅含 docx/pptx/xlsx→doc/ppt/xls、png/jpg/jpeg/gif/webp→image，**缺 video / audio 映射**，是本次问题根源之一） |

### 新增代码范围

| 文件 | 说明 |
|------|------|
| `backend/apps/knowledge/serializers.py` | 新增 `EXT_TO_FILE_TYPE` 全量「扩展名 → 类别」映射，及 `normalize_file_type()` 归一化函数（已是类别则原样返回；扩展名则映射；未知兜底 `other`）。映射覆盖 doc/docx/ppt/pptx/xls/xlsx/pdf/md/txt/html、png/jpg/jpeg/gif/webp→image、mp3/wav/ogg/flac/aac/m4a→audio、**mp4/webm/mov/avi/mkv/flv→video**、zip/rar→other |
| `backend/apps/knowledge/views.py` | 三处 `KnowledgeDoc` 入库统一调用 `normalize_file_type()`：回调 `UploadCallbackView`（原 `file_type=data['file_type']`）、直传 `FileUploadView`（原 `file_type=ext`）、批量 `BatchUploadView`（原 `file_type=ext`） |
| `backend/apps/knowledge/chunked_views.py` | 分片合并入库由本地 `_FILE_TYPE_MAP` 改为共享 `normalize_file_type()`，并同步更新 import |

> 说明：此前 `file_type` 字段（`KnowledgeDoc.FILE_TYPE_CHOICES` 为「类别」）在直传/批量路径存的是**原始扩展名**（如 `mp4`、`docx`），与模型 choices 不一致；回调路径存的是前端传入值。本次统一在入库前归一化为「类别」，使 `video/image/audio/...` 语义正确、与前端展示一致。

### 数据库变更

无（纯代码层映射逻辑）。**注意**：本次修复只影响新上传的记录；历史上已入库且 `file_type` 存成原始扩展名（如 `mp4`）的存量记录，如需回填为类别，需另行授权的数据订正（不属于本次代码范围）。

### Migration 文件

无。

### API 变更

无新增/删除接口。行为变化：新上传文档的 `file_type` 返回值由「扩展名」变为「类别」（`mp4` → `video`、`docx` → `doc`、`jpg` → `image` …）。

### 验证步骤

1. `python -m py_compile` 三个改动文件 → 语法通过
2. 直传 `xxx.mp4` → `KnowledgeDoc.file_type` 应为 `video`（旧为 `mp4`）
3. 直传 `xxx.avi` / `xxx.mkv` → 均应为 `video`
4. 直传 `xxx.mp3` → 应为 `audio`；`xxx.docx` → `doc`；`xxx.jpg` → `image`
5. 分片上传 `xxx.mkv`（merge 入库）→ `file_type` 应为 `video`
