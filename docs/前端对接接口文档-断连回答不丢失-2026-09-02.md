# 前端对接接口文档 — 断连/切走会话后回答不丢失（2026-09-02）

> **日期**：2026-09-02
> **后端分支**：main
> **变更类型**：**无接口/事件变更**，仅 SSE 流式写库时机与断连行为调整（前端**无需改核心逻辑**，可补一个体验点）

---

## 〇、本次变更

**没有新增/删除接口，没有事件结构变更。** 改动在 `POST /api/chat/ask/` 的流式内部：AI 回答从「流全部结束后才写库」改为「流式过程中增量写库 + 断连时后台拉完并写库」。

**解决的问题**：提问后等待回答时切到其他对话再回来，该 AI 回答会被中断、显示为空。

---

## 一、行为变化（对前端的影响）

| 场景 | 变更前 | 变更后 |
|------|--------|--------|
| 正常不打断 | `done` 后 `content` 完整 | 不变，`done` 后 `content` 完整 |
| 中途切走 / 断连 | 后端生成器直接退出，`content` 落库为空 → 回来看到空回答 | 后端后台把 LLM 流拉完并写库，`content` 最终为**完整回答** |

---

## 二、前端建议（可选体验点）

切走再切回会话时，前端一般会走 `GET /api/chat/conversations/{id}/`（或对应会话详情接口）重新拉取消息列表。后端现在会在断连后**后台继续生成并写库**，因此：

- 若拉取时发现某条 `role="assistant"` 消息的 `content` 为空（回答可能还在后台生成中），**稍等片刻重拉一次会话详情**即可看到完整内容，无需再依赖被中断的 SSE 流。
- 无需改动 SSE 接收逻辑，`start` / `token` / `suggested` / `references` / `references_detail` / `images` / `done` 事件序列和结构保持不变。

| 文件 | 变更 |

## 四、影响范围

- 仅 `POST /api/chat/ask/` 主 RAG 流式路径。
- 数据查询 / 网页分析 / 联网搜索 / 内建知识库 / 语音问答等旁路本次未改。
- 无数据库结构 / 字段 / 索引 / 约束变更。
