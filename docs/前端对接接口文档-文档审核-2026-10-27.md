# 前端对接接口文档 — 文档审核（2026-10-27）

> **日期**：2026-10-27
> **后端分支**：`feat/doc-review`（基于 `main` @ 09d4282）
> **认证说明**：所有接口均需携带 JWT Token，格式：`Authorization: Bearer <token>`
> **本文档面向**：前端对接同学，说明「管理员上传 → 对应审核人审核 → 通过后才可被检索」这套流程的接口用法。

## 一、审核模型

### 1.1 状态机

| `review_status` | 含义 | 能否被 AI 问答检索 |
|---|---|---|
| `pending` | 待审核（管理员上传后的默认状态） | ❌ |
| `approved` | 已通过 | ✅ |
| `rejected` | 已驳回（文件保留） | ❌ |

流转：

```
上传（非超管） → pending ──通过──→ approved ──→ 索引中 → indexed（可检索）
                    │
                    └──驳回──→ rejected ──上传者重新提交──→ pending
上传（超管）   → approved（免审，直接索引）
```

> ⚠️ `review_status` 与 `status` 是两个维度：
> `status` 是索引流水线（`uploaded/parsing/chunking/embedding/indexed/failed`），
> `review_status` 是审核状态。审核通过后 `status` 才开始走流水线，不会瞬间变成 `indexed`。

### 1.2 谁能审什么

| 文档形态 | 审核人 |
|---|---|
| 超管上传（`college_id`、`department_id` 均为空） | 无审核人，直接 `approved` |
| `department_id` 有值（部门级） | 该部门的审核员 |
| `department_id` 为空、`college_id` 有值（学院级） | 该学院的审核员 |
| 审核员自己上传 | 不可能——审核员没有上传权限 |

### 1.3 角色与权限

| 角色 | 上传 | 审核 | 说明 |
|---|---|---|---|
| `super_admin` | ✅ | ❌ | 上传免审；**不提供审核入口**，调审核接口返回 403 |
| `college_admin` / `admin` | ✅ | ❌ | 上传后 `pending` |
| `dept_admin` | ✅ | ❌ | 上传后 `pending` |
| `reviewer` | ❌ | ✅ | 新增角色。绑部门 → 审本部门；绑学院 → 审本学院学院级文档 |
| `user` | ❌ | ❌ | 只能用 AI 问答 |

> `reviewer` 账号的归属是**二选一**：`department` 或 `college`，不能同时有、也不能都没有（后台创建时校验）。

## 二、文档对象新增字段

`GET /api/knowledge/docs/`、`GET /api/knowledge/docs/{id}/`、以及所有上传接口返回的文档对象新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `review_status` | string | `pending` / `approved` / `rejected` |
| `reviewer` | int\|null | 审核人用户 ID |
| `reviewer_name` | string | 审核人用户名，未审为空串 |
| `reviewed_at` | datetime\|null | 审核时间 |
| `review_comment` | string | 审核意见；驳回时为驳回理由，通过时为空 |

## 三、接口详细

### 3.1 待审列表

```
GET /api/knowledge/reviews/pending/
权限：reviewer
```

Query 参数（均可选）：

| 参数 | 说明 |
|---|---|
| `page` / `page_size` | 分页 |
| `search` | 标题 / 文件名 / 上传者用户名 模糊匹配 |
| `file_type` | 文件类型（`pdf`/`doc`/`ppt`/`xls`/`image`…） |
| `start_date` / `end_date` | 上传时间范围，`YYYY-MM-DD` |

排序：上传时间**升序**（先传先审）。

响应（分页）：

```json
{
  "count": 2,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 128,
      "title": "2026年教学管理规范",
      "file_name": "教学管理规范.pdf",
      "file_type": "pdf",
      "file_ext": "pdf",
      "file_size": 524288,
      "status": "uploaded",
      "review_status": "pending",
      "reviewer_name": "",
      "reviewed_at": null,
      "review_comment": "",
      "college_name": "计算机与软件学院",
      "uploader_name": "sso_dept_admin",
      "uploader_college_name": "",
      "uploader_department_name": "教学管理部",
      "chunk_count": 0,
      "created_at": "2026-10-27T10:12:03+08:00",
      "created_at_display": "2026-10-27 10:12"
    }
  ]
}
```

> 审核员看到的范围由后端按账号归属自动收窄，前端不需要传部门/学院参数。

### 3.2 已审记录

```
GET /api/knowledge/reviews/history/
权限：reviewer
```

Query 参数：`action`（`approve`/`reject`/`resubmit`）、`search`（文档标题）、分页参数。

响应（分页）：

```json
{
  "count": 1,
  "results": [
    {
      "id": 31,
      "doc": 128,
      "doc_title": "2026年教学管理规范",
      "doc_file_name": "教学管理规范.pdf",
      "action": "reject",
      "action_display": "驳回",
      "reviewer": 37,
      "reviewer_name": "dept_reviewer_1",
      "comment": "缺少发文编号，请补充后重新提交",
      "created_at": "2026-10-27T16:20:11+08:00",
      "created_at_display": "2026-10-27 16:20"
    }
  ]
}
```

### 3.3 审核通过

```
POST /api/knowledge/docs/{id}/review/approve/
权限：reviewer
请求体：无
```

响应 `200`：返回该文档对象（同 3.1 单条结构，`review_status` 为 `approved`，`reviewer_name`、`reviewed_at` 已填充）。

后端行为：通过后异步派发「提取发布日期 / 解析分块 + 向量化 / AI 自动关联」三个任务，文档随后才开始进入索引流水线。

### 3.4 审核驳回

```
POST /api/knowledge/docs/{id}/review/reject/
权限：reviewer
请求体：{"comment": "驳回理由（必填，≤500 字）"}
```

响应 `200`：返回文档对象，`review_status` 为 `rejected`，`review_comment` 为驳回理由。文件保留，不删除。

`comment` 缺失或全为空白 → `400`。

### 3.5 重新提交审核

```
POST /api/knowledge/docs/{id}/review/resubmit/
权限：上传者本人（无需审核权限）
请求体：{"comment": "修改说明（可选）"}
```

响应 `200`：返回文档对象，`review_status` 回到 `pending`，`review_comment` 清空，`reviewer`/`reviewed_at` 置空。

仅 `rejected` 状态可重新提交；其他状态返回 `409`。

## 四、错误码

| HTTP | 场景 | 响应体 |
|---|---|---|
| `400` | 驳回理由为空 | `{"comment": ["驳回理由不能为空"]}` |
| `400` | 上传时账号既无学院也无部门 | `{"college_id": ["当前账号未归属任何学院或部门，无法上传（无对应审核人）"]}` |
| `403` | 非审核员调审核接口（含 `super_admin`） | `{"detail": "仅审核员可执行审核操作"}` |
| `403` | 文档不在本人审核范围 | `{"detail": "该文档不在你的审核范围内"}` |
| `403` | 非上传者调重新提交 | `{"detail": "只有上传者本人可以重新提交"}` |
| `404` | 文档不存在 | 标准 404 |
| `409` | 文档已被处理（重复审核 / 状态不符） | `{"detail": "...", "code": "REVIEW_CONFLICT"}` 或 `REVIEW_STATE_INVALID` |

## 五、前端页面建议

**审核页（reviewer 登录可见）**
- 列表直接调 3.1，字段用 `title` / `file_name` / `file_ext` / `file_size` / `created_at_display` / `uploader_name` / `uploader_department_name`
- 操作列两个按钮：通过（无需二次确认可加 loading）、驳回（弹窗必填理由，空时禁用提交按钮）
- 预览直接用现有的 `GET /api/knowledge/docs/{id}/preview/`，审核员对本部门/本学院文档有权限；**预览不依赖已索引**，未审核的文档也能看原件

**文档列表 / 详情**
- 增加审核状态徽章：`pending`（待审核，黄）、`approved`（已通过，绿）、`rejected`（已驳回，红，悬浮显示 `review_comment`）
- 只有 `rejected` 且当前用户是上传者时，显示「重新提交」按钮
- 上传成功后提示语建议改为「上传成功，等待审核」，不要写「已入库」

**状态提示**
- `review_status=approved` 但 `status!=indexed` 时，显示「审核已通过，正在建立索引」，避免用户误以为马上能搜到

---

## 六、注意事项

1. **超管没有审核入口**：`super_admin` 调 3.1~3.4 均 403，前端不要给超管渲染审核菜单。
2. **审核员没有上传入口**：`reviewer` 调任何上传接口均 403。审核页不要放上传按钮。
3. **存量文档**：本次上线前已存在的文档全部为 `approved`，不会因上线而消失。
4. **官网爬虫 / 图书馆摘要**：非上传来源的文档默认 `approved`，不进入审核流程。
5. `review_status` 只影响「能不能被 AI 问答检索」；后台文档列表仍按角色范围展示全部状态（管理员能看到待审文件）。
