# 前端对接接口文档 — 上传空文件/空文档拒绝（2026-09-10）

> **日期**：2026-09-10
> **后端分支**：main
> **认证说明**：所有接口均需携带 JWT Token，格式：`Authorization: Bearer <token>`
> **面向**：前端上传组件对接同学

---

## 〇、本次变更概述

上传接口新增「空文件拒绝」校验，分两类：

1. **0 字节文件（0KB）**：任何扩展名，全部上传入口直接拒绝。
2. **空文档**：Word / PDF / Excel / 纯文本等「有字节但提取不到任何正文内容」的文件，直传/批量时拒绝。

> 无新增 / 删除接口、无请求参数与响应结构变更，纯行为变化。前端老逻辑不会报错，但**建议**按第三节做体验优化。

---

## 一、各接口行为变化

| 接口 | 触发场景 | 返回 |
|------|---------|------|
| `POST /api/knowledge/upload/file/`（直传） | 0 字节文件；空 Word/PDF/Excel/纯文本 | `400`，`file: ["不能上传空文件（文件内容为空）"]` |
| `POST /api/knowledge/upload/batch/`（批量） | 0 字节文件；空纯文本（txt/md/csv 等全空白） | 该文件进 `failed`，`error: "不能上传空文件（文件内容为空）"`，其余文件不受影响 |
| `POST /api/knowledge/upload/sts/`（STS 凭证） | `file_size = 0` | `400`，`file_size: ["不能上传空文件（文件内容为空）"]` |
| `POST /api/knowledge/upload/callback/`（回调） | `file_size = 0` | `400`，`file_size: ["不能上传空文件（文件内容为空）"]` |
| `POST /api/knowledge/upload/chunk/init/`（分片初始化） | `file_size = 0` | `400`，`file_size: ["不能上传空文件（文件内容为空）"]` |

### 需要注意的边界

| 文件 | 结果 | 说明 |
|------|------|------|
| 0 字节文件 | ❌ 拒绝 | 任何扩展名 |
| 空 Word/PDF/Excel（新建后无内容） | ❌ 拒绝（直传） | 提取不到正文 |
| 扫描件 PDF（图片、无文字层） | ✅ 正常上传 | 后端已区分「空 PDF」与「扫描件」，不误伤 |
| 音视频 / 压缩包 / 3D / 设计源文件 | ✅ 正常上传 | 但不再调用 AI 填信息，`title`=文件名、`description`/`keywords` 为空 |

---

## 二、返回示例

### 直传 400

```json
{
  "file": ["不能上传空文件（文件内容为空）"]
}
```

### 批量部分失败

```json
{
  "success": [...],
  "failed": [
    { "file_name": "空的.txt", "error": "不能上传空文件（文件内容为空）" }
  ],
  "total_count": 3,
  "success_count": 2,
  "failed_count": 1
}
```

---

## 三、前端对接建议

1. **0 字节预校验（强烈建议）**：文件选择后，用浏览器 `file.size === 0` 直接拦截并提示「不能上传空文件」，不发请求，体验更好。这是前端唯一能提前判断的空文件场景。

```js
if (file.size === 0) {
  // 提示：不能上传空文件
  return;
}
```

2. **空文档（空 Word/PDF）**：前端**无法**预判，需处理后端 `400` 与批量 `failed` 列表，把 `file` / `error` 里的文案直接展示给用户即可。

3. **音视频/压缩包上传后**：返回的 `description`、`keywords` 可能为空、`title` 等于文件名，这是预期行为，前端无需特殊处理（若产品要求这类文件也填信息，需另行沟通）。
