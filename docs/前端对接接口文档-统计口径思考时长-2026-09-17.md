# 前端对接说明 — 统计口径变更：平均响应时长 → 平均思考时长

> 最后更新：2026-09-17　｜　后端：GJ-ml
> 一句话总结：**接口、字段名、类型全部不变**；只有 `avg_response_sec`（及管理端 `avg_response_ms`）这两个字段的**统计口径**变了，前端需要同步调整页面上的展示文案。

---

## 一、本次变更

| 项目 | 变更前 | 变更后 |
|------|--------|--------|
| 字段名 | `avg_response_sec` | **不变** |
| 字段类型 | float | **不变** |
| 接口路径 / 请求方式 | `GET /api/platform/stats/` | **不变** |
| 统计口径 | 平均**响应时长** = 整条回答完整生成完的总耗时（含全部流式输出 + 推荐问题生成） | 平均**思考时长** = 用户发送问题 → AI 输出第一个字的等待时间 |
| 数值预期 | 均值约 7.5s | 显著下降（秒级，预期 1~2s 量级） |

> 背景：原口径把"AI 打字输出的全部时间"也算进去（答案越长数字越大），与用户感知的"思考多久"不符，故调整为"思考时长"（即前端"思考中"转圈那段时间）。

---

## 二、前端需要改什么（清单）

1. **首页「平台数据概览」**：`avg_response_sec` 的标签文案
   - 若当前写的是「平均响应时长」→ 建议改为「**平均思考时长**」
   - 单位仍为秒，展示逻辑不变
2. **管理后台 · 查询日志统计页**（`/api/admin/logs/query/stats/` 的 `avg_response_ms`）：
   - 标签若为「平均响应时长」→ 同步改为「**平均思考时长**」（单位毫秒）
   - 管理端 Dashboard 查询日志块（`/api/admin/logs/dashboard/` 的 blocks 内 `avg_response_ms`）同理
3. **检查数值相关的 UI 假设**：
   - 如果有基于旧数值量级（~7.5s）的阈值着色 / 进度条 / 预警规则，需要按新量级（1~2s）重新校准
4. **取数逻辑：零改动**。字段名、类型、路径、请求方式、鉴权要求全部不变，不需要改任何请求代码。

---

## 三、接口说明（未变部分一并给出，便于对照）

### 3.1 GET /api/platform/stats/ — 首页「平台数据概览」

**权限**：AllowAny（游客可见，无需 Token）　**缓存**：服务端缓存 120 秒

**响应示例**：

```json
{
    "users": 9,
    "storage_bytes": 249585745,
    "docs": 86,
    "queries": 246,
    "avg_response_sec": 7.5,
    "sensitive_blocks": 0,
    "logins": 482
}
```

**字段说明**：

| 字段 | 类型 | 说明 | 本次变化 |
|------|------|------|----------|
| `users` | int\|null | 用户总数（role=user 师生账号，不含管理员） | 无 |
| `storage_bytes` | int\|null | 存储总量（字节） | 无 |
| `docs` | int\|null | 资料总数 | 无 |
| `queries` | int\|null | 查询总数（AI 问答累计） | 无 |
| `avg_response_sec` | float\|null | **平均思考时长（秒，1 位小数）**：发送问题到 AI 输出首字；仅统计 >0 的有效记录 | ⚠️ 口径变更 |
| `sensitive_blocks` | int\|null | 敏感拦截累计 | 无 |
| `logins` | int\|null | 登录次数累计 | 无 |

**错误/边界行为（原有约定，未变）**：
- 单项计算失败 → 该项 `null`，结构稳定，前端按 0/缺省兜底
- 七项全 `null`（数据库不可用）→ HTTP **503**，前端走错误态
- 服务端 120s 缓存 → 刷新后最多延迟 2 分钟更新，属正常现象

### 3.2 GET /api/admin/logs/query/stats/ — 管理端查询日志统计（超管）

仅一个字段口径变化：

| 字段 | 类型 | 说明 | 本次变化 |
|------|------|------|----------|
| `avg_response_ms` | float | **平均思考时长（毫秒）**：发送问题到 AI 输出首字 | ⚠️ 口径变更 |

其余字段（`total` / `today` / `this_week` / `this_month` / `avg_hit_count` / `like_rate` / `by_feedback`）不变。管理端 Dashboard 查询日志块中的 `avg_response_ms` 同口径。

## 四、上线与联调注意事项

1. **历史数据过渡期**：口径切换前已产生的记录仍按旧口径存值（均值偏高）。切换初期该数字会"先偏高、随新提问逐步下降"，属预期行为，不是 bug；后端可视情况清理存量数据（若清理，数值会立即变为新口径量级）。
2. **验证方法**：上线后发起一次新提问，在管理端查询日志列表中查看最新记录的 `response_ms`，应为首字等待毫秒数（远小于旧的整条耗时）；公开统计接口受 120s 缓存影响，稍等片刻刷新即可看到新值。
3. **字段名虽然没变**，含义已变为"思考时长"——后续新页面请直接按新语义使用，不要再按"整条回答耗时"理解。
