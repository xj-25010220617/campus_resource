## 0. 测试前置

### 0.1 环境变量

测试时建议把以下变量提前 export，方便 `curl` 直接复用：

```bash
# 基础地址
export BASE_URL="http://localhost:8000/api"

# 三种角色 Token（从 POST /api/auth/login/ 或 SSO 回调获取）
export TOKEN_USER="<普通 user 的 JWT>"
export TOKEN_ADMIN="<学院 admin 的 JWT>"
export TOKEN_SUPER="<super_admin 的 JWT>"

# 公共 ID（按实际数据库填写）
export CONV_ID=1           # 当前用户自己的会话 ID
export OTHER_CONV_ID=999   # 别人的会话 ID
export MSG_ID=1            # 自己会话里的 AI 消息 ID
export OTHER_MSG_ID=888    # 别人会话里的 AI 消息 ID
export USER_ID=10          # 要管理的普通用户 ID
export UPLOAD_LOG_ID=1     # 已存在的上传日志 ID
export DOC_ID=42           # KnowledgeDoc 主键
```

### 0.2 通用响应约定

- 成功：`200` / `201` / `204`，按接口文档
- 未登录：`401 {"detail": "Authentication credentials were not provided."}`
- 无权限：`403 {"detail": "...", "code": "PERMISSION_DENIED"}` 或仅 `{"detail": "..."}`
- 资源不存在：`404 {"detail": "...", "code": "NOT_FOUND"}` 或 `{"detail": "No Xxx matches the given query."}`
- 参数错误：`400 {"field": ["..."]}` 或 `{"detail": "...", "code": "VALIDATION_ERROR"}`
- 分页列表统一为 `{count, next, previous, results: [...]}`，**越界页码返回 404 `{"detail": "无效页面。"}`**（DRF `PageNumberPagination` 默认行为，不是 bug）
- 分页 URL 前缀统一为 `/api/...`，调用 `/chat/...` 不带 `/api` 会 404 `Page not found`
- **删除语义**：本次覆盖的所有 DELETE 接口（会话、消息、上传日志）均为**硬删除**，**无回收站、无 is_deleted**，执行前请确保数据可丢或已备份

### 1.5 `DELETE /api/chat/conversations/{id}/` — 删除会话

> **删除类型**：**硬删除（物理删除）**。当前实现没有 `is_deleted` / `deleted_at` 等软删除字段，
> 调用 `ModelViewSet.destroy()` 会直接执行 `DELETE FROM chat_conversation WHERE id={id}`，
> 并通过 `ON DELETE CASCADE` 级联清空所有 `chat_message` 记录。**不存在回收站，删除后无法恢复**。
>
> 与之关联：
> - `query_log` 上的 `conversation_id` 会置 `NULL`（模型定义为 `on_delete=SET_NULL`），日志不丢
> - 前端"最近会话"列表会立刻少一项，与下次 `GET /api/chat/conversations/` 计数 `count` 同步
>
> 如需软删除能力（误删恢复 / 审计追溯），需要先给 `Conversation` / `ChatMessage` 加 `is_deleted` 字段 + 重写 `get_queryset` + 重写 `perform_destroy`，改动不在本次接口测试覆盖范围内。

**测试用例**

| # | 场景 | 期望 |
|---|---|---|
| 1.5.1 | 删除自己的会话 | 204 No Content |
| 1.5.2 | 删除别人的会话 | 404 |
| 1.5.3 | 二次删除 | 404 |
| 1.5.4 | 验证级联（硬删） | 删除后 `GET /api/chat/conversations/{id}/` 返回 404；直接查 `SELECT count(*) FROM chat_message WHERE conversation_id={id}` 应为 0 |
| 1.5.5 | 验证 query_log 保留 | `SELECT count(*) FROM query_log WHERE conversation_id={id}` 删除后可能 > 0，但 `conversation_id` 已被置 `NULL` |
| 1.5.6 | 未登录 | 401 |

## 2. Chat — AI 问答（1 个）

### 2.1 `POST /api/chat/ask/` — AI 问答（SSE 流式）

**权限**：`IsAuthenticated`

**请求体**

```json
{
  "conversation_id": null,
  "question": "成都东软学院有哪些二级学院？"
}
```

> 不传 `conversation_id` 时，后端会创建新会话并自动关联。流式响应通过 `text/event-stream` 返回，最终消息会落库 `chat_message`。

**测试用例**

| # | 场景 | 期望 |
|---|---|---|
| 2.1.1 | 新会话提问（不传 conversation_id） | 200，`Content-Type: text/event-stream`，响应中包含分块 `data: ...\n\n`，最终消息写入 DB；之后再 `GET /api/chat/conversations/` 能看到新会话 |
| 2.1.2 | 已有会话追问 | 200，SSE 流正常返回；提问后 `GET /api/chat/conversations/$CONV_ID/` 看到 `messages` 长度 +2 |
| 2.1.3 | 必填参数校验 | 缺 `question` 时返回 400 `{"question": ["This field is required."]}` |
| 2.1.4 | 未登录 | 401 |
| 2.1.5 | SSE 校验 | 客户端应能逐块渲染 `data:` 后内容；首块通常会带 `conversation_id` 或 `references` 元信息（按实现而定，建议在浏览器 Network 面板观测） |

**手动验证 SSE 的小技巧**

```bash
curl -N -X POST "$BASE_URL/chat/ask/" \
  -H "Authorization: Bearer $TOKEN_USER" \
  -H "Content-Type: application/json" \
  -d '{"question":"校园网如何开户？"}'
```

`-N` 关闭缓冲，可以看到一帧一帧的 `data: ...`。

## 6. Knowledge — AI 提取发布日期（1 个）

> 路由：`POST /api/knowledge/docs/{id}/extract-freshness/`
> 权限：`super_admin` 任意文档；`admin` 仅自己上传的文档；`user` 拒绝。

### 6.1 `POST /api/knowledge/docs/{id}/extract-freshness/` — AI 提取发布日期

**Query 参数**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `async` | bool | `true` | `true` → Celery 入队（202）；`false` → 同步阻塞（200）。Celery 不可用时无论取值都降级同步。 |

**期望响应（异步 202）**

```json
{
  "task_id": "8f4a1b3c-7d2e-4f9a-b0c1-1e2f3a4b5c6d",
  "status": "queued",
  "doc_id": 42
}
```

**期望响应（同步 200）**

```json
{
  "freshness_date": "2025-03-15",
  "confidence": "high",
  "source_excerpt": "本资料适用于 2025 年春季学期，修订日期 2025-03-10",
  "raw_response": { "parsed": {...}, "raw": "..." }
}
```

**测试矩阵**

| # | 场景 | Token | `async` | 期望 |
|---|---|---|---|---|
| 6.1.1 | 超管异步 | super_admin | `true`（默认） | 202 `{"task_id": "...", "status": "queued", "doc_id": <int>}` |
| 6.1.2 | 超管同步 | super_admin | `false` | 200，返回 `freshness_date / confidence / source_excerpt / raw_response` |
| 6.1.3 | admin 对自己上传文档异步 | admin | `true` | 202 |
| 6.1.4 | admin 对自己上传文档同步 | admin | `false` | 200 |
| 6.1.5 | admin 对他人上传文档异步 | admin | `true` | 403 `{"detail": "只能对自己上传的文档触发 AI 日期提取", "code": "PERMISSION_DENIED"}` |
| 6.1.6 | admin 对他人上传文档同步 | admin | `false` | 403 |
| 6.1.7 | 普通 user 调用 | user | `true` | 403 `{"detail": "只有管理员可以触发 AI 日期提取", "code": "PERMISSION_DENIED"}` |
| 6.1.8 | 文档不存在 | super_admin | `true` | 404 `{"detail": "No KnowledgeDoc matches the given query.", "code": "NOT_FOUND"}` |
| 6.1.9 | 同步模式下文档不存在 | super_admin | `false` | 200 `{"detail": "文档不存在", "code": "NOT_FOUND"}`（特殊路径，见视图实现） |
| 6.1.10 | 图片/视频/音频类型 | super_admin | `false` | 200 `{"freshness_date": null, "confidence": "none", "source_excerpt": "文件类型 image 暂不支持文本提取", "raw_response": {}}` |
| 6.1.11 | 文字清晰的高置信度 | super_admin | `false` | 200，`confidence=high`，`freshness_date` 非空 |
| 6.1.12 | 文字模糊的 LLM 推断 | super_admin | `false` | 200，`confidence=medium` 或 `low` |
| 6.1.13 | 完全无日期线索 | super_admin | `false` | 200，`freshness_date=null`，`confidence=none` |
| 6.1.14 | Celery 不可用降级 | super_admin | `true` | 200 直接返回同步结果（可临时停 Celery worker 验证） |
| 6.1.15 | 未登录 | — | — | 401 `{"detail": "Authentication credentials were not provided.", "code": "UNAUTHORIZED"}` |
| 6.1.16 | Celery 任务可被查到 | super_admin | `true` | 拿到 `task_id` 后到 Flower / `celery -A config result` 里能查到执行结果；执行完 `KnowledgeDoc.freshness_date` 已更新 |

**异步任务回调校验**

```bash
# 6.1.1 拿到 task_id 后等几秒查结果
celery -A config inspect result $TASK_ID -d celery@<host>

# 或直接看数据库
mysql -h$DB_HOST -u$DB_USER -p$DB_PASSWORD $DB_NAME \
  -e "SELECT id, title, freshness_date FROM knowledge_doc WHERE id=$DOC_ID;"
```

## 9. 常见问题 / 排查清单

1. **SSE 一直接不到内容**：检查 Nginx 是否有 `proxy_buffering off`，本地用 `curl -N` 验证。
2. **401 出现但 Token 是新的**：确认 `Authorization: Bearer <token>` 拼写；JWT 是否过期；`/api/auth/refresh/` 续签。
3. **上传日志查不到结果**：列表接口是 admin+，先用 admin/super_admin token；非管理员会直接 403。
4. **AI 提取总是 `confidence=none`**：先用 PDF/DOCX 这种有文本的类型测试；图片/视频本来就返回 `none`。
5. **异步任务迟迟不更新 `freshness_date`**：确认 Celery worker 已启动（`celery -A config worker -l info`）；Redis broker 是否可达。
6. **删除自己报 403**：这是预期行为，请用别的管理员账号测试删除。
