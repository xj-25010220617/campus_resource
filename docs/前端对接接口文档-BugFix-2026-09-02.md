## 一、登录日志统计 — by_hour 空值兼容

### 1.1 接口

```
GET /api/admin/logs/login/stats/
```

**权限**：super_admin

### 1.2 变更说明

**修复前**：当数据库中存在 `created_at` 为 `NULL` 的登录日志时，`by_hour` 中 `ExtractHour('created_at')` 返回 `None`，对 `None` 做格式化 `f'{hour:02d}'` 触发 `TypeError`，接口返回 500。

**修复后**：`hour` 为 `None` 时，`by_hour` 中对应项为：

```json
{
  "key": "-1",
  "label": "未知",
  "count": 1
}
```

### 1.3 完整响应示例（HTTP 200）

```json
{
  "total": 128,
  "today": 12,
  "this_week": 45,
  "this_month": 98,
  "success_count": 110,
  "fail_count": 18,
  "by_success": [
    { "key": "true",  "label": "成功", "count": 110 },
    { "key": "false", "label": "失败", "count": 18 }
  ],
  "by_type": [
    { "key": "jwt",      "label": "账号密码", "count": 80 },
    { "key": "sso",      "label": "SSO",      "count": 40 },
    { "key": "sso_mock", "label": "SSO Mock", "count": 8 }
  ],
  "by_hour": [
    { "key": "-1", "label": "未知",  "count": 2 },
    { "key": "0",  "label": "00:00", "count": 1 },
    { "key": "8",  "label": "08:00", "count": 15 },
    { "key": "9",  "label": "09:00", "count": 22 },
    { "key": "10", "label": "10:00", "count": 18 },
    { "key": "14", "label": "14:00", "count": 20 },
    { "key": "20", "label": "20:00", "count": 5 }
  ]
}
```

### 1.4 前端适配建议

- `by_hour` 中 `key === "-1"` 的项代表 `created_at` 为空的脏数据，前端可**过滤不展示**，也可展示为"未知时间"。
- 其余 `by_hour` 项的 `key` 仍为 `"0"` ~ `"23"` 的字符串，`label` 仍为 `"00:00"` ~ `"23:00"` 格式，**无变化**。

## 二、AI 问答消息反馈 — 支持取消

### 2.1 接口

```
POST /api/chat/message/{id}/rate/
```

**权限**：消息所属用户本人

### 2.2 变更说明

**修复前**：`rating` 仅接受 `"like"` / `"dislike"`，点赞后只能切换为点踩，**无法取消回到无反馈状态**。

**修复后**：`rating` 新增 `"none"` 选项，表示取消反馈。

### 2.3 请求参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| rating | string | 是 | `"like"` = 点赞 / `"dislike"` = 点踩 / **`"none"` = 取消反馈（新增）** |

### 2.4 请求示例

```json
// 点赞
POST /api/chat/message/42/rate/
{ "rating": "like" }

// 点踩
POST /api/chat/message/42/rate/
{ "rating": "dislike" }

// 取消反馈（新增）
POST /api/chat/message/42/rate/
{ "rating": "none" }
```

### 2.5 响应示例（HTTP 200）

```json
// 点赞
{ "status": "ok", "rating": "like" }

// 点踩
{ "status": "ok", "rating": "dislike" }

// 取消反馈
{ "status": "ok", "rating": null }
```

### 2.6 前端交互逻辑建议

```
初始状态:     无反馈 → 点击赞 → like
              无反馈 → 点击踩 → dislike

like 状态:    点击赞 → 取消 → none（回到无反馈）
              点击踩 → 切换 → dislike

dislike 状态: 点踩踩 → 取消 → none（回到无反馈）
              点踩赞 → 切换 → like
```

即：**点击当前已选中的按钮 = 取消**，点击另一个按钮 = 切换。

### 2.7 错误响应

| HTTP 状态码 | 场景 | 响应 |
|------------|------|------|
| 400 | `rating` 不在 `like` / `dislike` / `none` 中 | `{"rating": ["\"xxx\" is not a valid choice."]}` |
| 403 | 非消息所属用户 | `{"detail": "无权对此消息进行反馈"}` |
| 404 | 消息不存在 | `{"detail": "Not found."}` |

## 三、部门管理 — 移除 sort_order 字段

### 3.1 列表接口

```
GET /api/admin/departments/
```

**权限**：所有管理员（super_admin / college_admin / dept_admin / admin）

### 3.2 新建接口

```
POST /api/admin/departments/
```

**权限**：仅 super_admin

### 3.3 变更说明

**变更前**：

列表响应和新建请求体都包含 `sort_order` 字段：

```json
// GET 响应（变更前）
{
  "id": 1,
  "name": "党政管理部门",
  "parent": null,
  "sort_order": 2,
  "children": [...]
}

// POST 请求体（变更前）
{
  "name": "新部门",
  "parent": null,
  "sort_order": 5
}
```

**变更后**：

`sort_order` 字段从响应和请求体中**移除**，排序由后端按 `sort_order` + `id` 自动管理，前端无需关心：

```json
// GET 响应（变更后）
{
  "id": 1,
  "name": "党政管理部门",
  "parent": null,
  "children": [...]
}

// POST 请求体（变更后）
{
  "name": "新部门",
  "parent": null
}
```

### 3.4 完整响应示例（GET，HTTP 200）

```json
[
  {
    "id": 1,
    "name": "校级领导",
    "parent": null,
    "children": [
      { "id": 8, "name": "党委书记", "parent": 1, "children": [] },
      { "id": 9, "name": "校长",     "parent": 1, "children": [] },
      { "id": 10, "name": "副校长",  "parent": 1, "children": [] }

  {
    "id": 2,
    "name": "党政管理部门",
    "parent": null,

      { "id": 12, "name": "党委组织部/人力资源部",          "parent": 2, "children": [] }
```

### 3.5 前端适配

- **移除**部门列表/表格中的 `sort_order`（排序序号）列
- **移除**新建/编辑部门表单中的 `sort_order` 输入框

## 四、知识库关键词 — 上传去重 & 添加去重

### 4.1 涉及接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/knowledge/docs/` | POST | 文档上传（JSON / Multipart / 批量） |
| `/api/knowledge/docs/{id}/keywords/` | POST | 为文档手动添加关键词 |

**权限**：管理员（super_admin / admin）

### 4.2 问题描述

**修复前**：

1. **上传时重复创建**：上传文档时，用户手填关键词与 AI 自动提取关键词可能重叠（如都包含"学校简介"），后端用 `Keyword.objects.create()` 直接写入，导致同一文档下出现**多条相同 phrase** 的关键词记录。
2. **手动添加报 409**：上传完成后，前端调用 `keywords/create/` 添加相同关键词时，唯一性校验 `Keyword.objects.filter(doc=doc, phrase=...).exists()` 命中已有记录，返回 409：

```json
HTTP 409 CONFLICT
{
  "detail": "关键词 \"学校简介\" 已存在于此文档中",
  "code": "CONFLICT"
}
```

**修复后**：

1. **上传去重**：所有上传接口（JSON / Multipart / 批量）改为 `get_or_create` + 内存 `set` 去重，同一文档内不会创建重复关键词。
2. **手动添加幂等**：`keywords/create/` 接口不再返回 409，重复添加时返回 **200 + 已有关键词记录**（幂等），行为与上传去重保持一致。

### 4.3 接口详情 — 手动添加关键词

```
POST /api/knowledge/docs/{doc_id}/keywords/
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phrase | string | 是 | 关键词或关键语句 |
| match_type | string | 否 | `exact` / `fuzzy`（默认）/ `semantic` |
| weight | integer | 否 | 权重 1-10，默认 1 |

**变更前响应**（关键词已存在时）：

```json
HTTP 409 CONFLICT
{
  "detail": "关键词 \"学校简介\" 已存在于此文档中",
  "code": "CONFLICT"
}
```

**变更后响应**（关键词已存在时，幂等返回已有记录）：

```json
HTTP 200 OK
{
  "id": 123,
  "phrase": "学校简介",
  "match_type": "fuzzy",
  "weight": 1,
  "created_by_name": "admin",
  "created_at": "2026-09-02T10:30:00Z"
}
```

**首次创建响应**（不变）：

```json
HTTP 201 CREATED
{
  "id": 124,
  "phrase": "学校简介",
  "match_type": "fuzzy",
  "weight": 1,
  "created_by_name": "admin",
  "created_at": "2026-09-02T10:35:00Z"
}
```

### 4.4 上传接口关键词去重

所有上传接口的 `keywords` 参数行为变更：

| 场景 | 变更前 | 变更后 |
|------|--------|--------|
| 用户手填 + AI 提取有重叠 | 创建重复记录 | 自动去重，只保留一条 |
| 关键词列表内有重复 | 创建重复记录 | 自动去重，只保留一条 |
| 数据库已存在相同 phrase | 创建重复记录 | `get_or_create` 跳过，不重复创建 |

上传请求参数和响应格式**不变**，前端无需修改上传逻辑。

### 4.5 前端适配

- **添加关键词**：`keywords/create/` 不再返回 409，前端**移除**对 409 的特殊处理/提示弹窗
- **添加关键词**：响应状态码可能是 **201**（新建）或 **200**（已存在），前端按成功处理即可
- **上传文档**：无需任何修改，去重逻辑在后端自动完成

## 五、文档预览 — 图片/音频/视频浏览器内联显示

### 5.1 接口

```
GET /api/knowledge/docs/{id}/preview/
```

**权限**：管理员（super_admin / admin / college_admin / dept_admin）；普通用户不可用

### 5.2 问题描述

**修复前**：上传到 OSS 的文件未设置 `Content-Type`，OSS 默认存储为 `application/octet-stream`。预览接口返回的签名 URL 未覆盖 MIME 类型，浏览器收到 `application/octet-stream` 后**触发下载而非内联显示**：

- 图片文件（png/jpg/gif/webp 等）→ 下载而非 `<img>` 渲染
- 音频文件（mp3/wav 等）→ 下载而非 `<audio>` 播放
- 视频文件（mp4/webm 等）→ 下载而非 `<video>` 播放
- PDF 文件 → 下载而非浏览器内置阅读器打开

**修复后**：预览 URL 通过 OSS `response-content-type` 签名参数**强制覆盖**响应 MIME 类型，浏览器可直接内联显示。

### 5.3 响应格式（无变化）

接口响应的 JSON 结构不变，仍然是：

```json
// 图片
{
  "preview_type": "url",
  "content": "https://oss.xxx.com/knowledge/...?sign=xxx&response-content-type=image%2Fpng",
  "file_type": "image",
  "file_name": "校园风景.png"
}

// 音频
{
  "preview_type": "url",
  "content": "https://oss.xxx.com/knowledge/...?sign=xxx&response-content-type=audio%2Fmpeg",
  "file_type": "audio",
  "file_name": "校歌.mp3"
}

// 视频
{
  "preview_type": "url",
  "content": "https://oss.xxx.com/knowledge/...?sign=xxx&response-content-type=video%2Fmp4",
  "file_type": "video",
  "file_name": "宣传片.mp4"
}

// 文档（PDF/Word/PPT 等）
{
  "preview_type": "url",
  "content": "https://oss.xxx.com/knowledge/...?sign=xxx&response-content-type=application%2Fpdf",
  "file_type": "document",
  "file_name": "培养方案.pdf"
}
```

### 5.4 支持的 MIME 类型覆盖

| 文件类别 | 扩展名 | Content-Type |
|---------|--------|-------------|
| **图片** | png | `image/png` |
| | jpg / jpeg | `image/jpeg` |
| | gif | `image/gif` |
| | webp | `image/webp` |
| | bmp | `image/bmp` |
| | svg | `image/svg+xml` |
| **音频** | mp3 | `audio/mpeg` |
| | wav | `audio/wav` |
| | ogg | `audio/ogg` |
| **视频** | mp4 | `video/mp4` |
| | webm | `video/webm` |
| | mov | `video/quicktime` |
| **文档** | pdf | `application/pdf` |
| | doc / docx / ppt / pptx / xls / xlsx | 对应 Office MIME 类型 |

> 未在映射表中的扩展名不传 `content_type`，由 OSS 返回原始存储的类型（通常为 `application/octet-stream`）。

### 5.5 前端适配

- **无需任何修改**：前端 `<img src="content">` / `<audio src="content">` / `<video src="content">` 逻辑不变
- **行为变化**：原来触发下载的图片/音视频现在可以直接内联显示
- **AI 对话中的图片**：同样修复，对话中的图片预览 URL 也强制返回正确 MIME 类型
