## 一、`images` 事件详解

### 1.1 触发时机

每次文字问答（`POST /api/chat/ask/`）在 `references` / `references_detail` 事件之后、`done` 事件之前，**若检索到与问题相关的图片**则下发一次 `images` 事件；无匹配图片则不下发。

### 1.2 事件在完整流中的顺序

```
event: start
event: token          （多条，逐字）
event: suggested      （3 个追问，可选）
event: references     （普通用户）
event: references_detail  （admin/super_admin）
event: images         （新增，可选，本次变更）
event: done
```

### 1.3 data 格式

`images` 事件的 `data` 是一个**数组**，元素结构如下：

```json
[
  {
    "doc_id": 123,
    "doc_title": "校园平面图",
    "description": "成都东软学院校园平面图，含各教学楼与宿舍分布",
    "preview_url": "https://oss.example.com/knowledge/school/0/2026-09/abc123.jpg?Expires=...&Signature=..."
  },
  {
    "doc_id": 88,
    "doc_title": "学校 logo",
    "description": "成都东软学院校徽",
    "preview_url": ""
  }
]
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `doc_id` | integer | 知识文档 ID（`KnowledgeDoc.id`） |
| `doc_title` | string | 图片文档标题 |
| `description` | string | 图片描述（AI 视觉识别生成，截断 200 字） |
| `preview_url` | string | 图片签名预览 URL（内联显示，非下载）；**为空字符串 `""` 时前端跳过该条**（OSS 未配置或对象缺失） |

### 1.4 关键点

- **直接展示方式**：`preview_url` 是「内联预览」URL（不带 `Content-Disposition: attachment`），前端直接 `<img src="preview_url">` 即内联显示，浏览器不会触发下载。有效期 **3600 秒**。
- **对所有人下发**：`images` 事件没有角色门槛（普通用户也能收到），后端已按权限过滤为「公开可见」的图片。
- **召回数量**：普通提问最多召回 **4** 张；当问题含明确找图意图（`图片/照片/海报/logo/图标/截图/设计图/示意图`）时最多召回 **8** 张，且回答文本会附带「已为你找到相关图片」的提示。

## 二、前端适配

### 2.1 消费方式

沿用现有 `fetch + ReadableStream`（`EventSource` 不支持 POST body），在 SSE 行解析中新增 `images` 事件分支：

```javascript
// 事件回调里新增
onImages: (data) => {
  // data 为数组 [{doc_id, doc_title, description, preview_url}]
  const valid = (data || []).filter(img => img.preview_url);
  valid.forEach(img => {
    renderImage(img.doc_title, img.preview_url);
  });
}
```

### 2.2 渲染示例（React）

```jsx
{images.map(img => img.preview_url && (
  <div key={img.doc_id} className="answer-image">
    <img src={img.preview_url} alt={img.doc_title} loading="lazy" />
    <span>{img.doc_title}</span>
  </div>
))}
```

### 2.3 注意

1. **务必过滤空 `preview_url`**：值为 `""` 时不要渲染 `<img src="">`。
2. 图片应渲染在**当前 AI 回答气泡内**（回答下方），而非引用列表。
3. `preview_url` 为一次性签名 URL、有时效（3600s），不要在本地长期缓存；重新进入历史会话时如需回看，可重新触发问答或另行拉取预览。
4. 该事件**不影响**现有 `token` 累加逻辑，图片渲染可与文字流并行/在其后追加。

## 四、联调建议

1. 先在知识库上传一张图片（标题/描述含关键词，如「校园平面图」）。
2. `POST /api/chat/ask/` 提问「校园平面图」→ 观察 SSE 流末尾出现 `event: images`，`data[0].preview_url` 非空。
3. 提问「帮我找学校 logo 的图片」→ 观察召回更多图片、回答文本提及图片。
4. 提问一个与图片无关的问题 → 无 `images` 事件，回答不受影响。
