## 一、问题背景（现象与根因）

### 1.1 现象

**现象 A — 下载文件名与原文件名不一致**
上传的文件叫 `课程资料 第一章.pdf`，下载下来却叫 `ab12cd34ef56.pdf`（一串 12 位随机字符）。

**现象 B — 点击下载，页面"跳转一下 → 回到原页面 → 才开始下载"**
点击下载按钮，当前页面闪一下 / URL 跳变，然后回到原页面，右下角才弹出下载。

### 1.2 根因

**根因 1（文件名不一致）**：上传时 OSS 对象名是**随机 UUID**，例如 `knowledge/college/1/2026-09/ab12cd34ef56.pdf`。这是后端有意为之（防止同名文件相互覆盖），**原始文件名只存在数据库 `file_name` 字段里**，OSS 对象本身不叫原始文件名。

**根因 2（文件名不一致）**：此前生成签名下载 URL 时没有携带 `Content-Disposition` 响应头覆盖，OSS 默认按对象名（UUID）作为下载文件名返回。

**根因 3（跳转现象）**：`Content-Disposition: attachment` 响应头让浏览器把文件判定为"附件下载"。若前端用**当前标签页直接导航**去打开这个 URL（如 `window.location.href = url` 或 `<a href>` 不带 `target`），浏览器会先发起页面跳转，收到 attachment 后**中止跳转**、触发下载、退回原页面——于是出现"跳转一下又回来才下载"。**这是前端交互写法问题，不是后端 bug。**

## 二、后端改动说明

### 2.1 核心机制

签名 URL 增加 `response-content-disposition` 响应头覆盖（阿里云 OSS 官方支持），让下载文件的文件名使用数据库里的原始文件名：

```
Content-Disposition: attachment; filename="<ASCII 回退>"; filename*=UTF-8''<百分号编码>
```

其中 `filename*=UTF-8''` 为 RFC 5987 编码，**支持中文文件名**。对存量文档立即生效，**无需重新上传**（原始文件名已在数据库）。

### 2.2 字段变化

| 字段 | 类型 | 语义 | 有效期 |
|------|------|------|--------|
| `download_url`（**新增**） | string | **附件下载** URL，浏览器保存的文件名 = 上传时的原始文件名 | 7 天（604800s） |
| `oss_url`（**语义变更**） | string | **签名内联预览** URL，无 `Content-Disposition` 覆盖，浏览器新标签页打开时**内联显示**（PDF/图片/音视频），不会触发下载 | 7 天（604800s） |

**注意**：
- 两个字段名对前端是**向后兼容**的——`oss_url` 字段名没变，只是内容从"永久原始 URL"变成了"签名预览 URL"。
- 两个 URL 都是**限时签名 URL**，过期后访问返回 403。前端不要缓存超过 7 天，也不要把它们当永久链接存库 / 分享给他人。

### 2.3 文档详情接口响应示例

`GET /api/knowledge/docs/{id}/` 关键字段（截取）：

```json
{
  "id": 1024,
  "file_name": "课程资料 第一章.pdf",
  "oss_key": "knowledge/college/1/2026-09/ab12cd34ef56.pdf",
  "oss_url": "https://campus-resourse.oss-cn-chengdu.aliyuncs.com/knowledge/college/1/2026-09/ab12cd34ef56.pdf?OSSAccessKeyId=xxx&Expires=xxx&Signature=xxx",
  "download_url": "https://campus-resourse.oss-cn-chengdu.aliyuncs.com/knowledge/college/1/2026-09/ab12cd34ef56.pdf?response-content-disposition=attachment%3B%20filename%3D...&OSSAccessKeyId=xxx&Expires=xxx&Signature=xxx"
}
```

`download_url` 与 `oss_url` 指向**同一个 OSS 对象**，区别只在 `download_url` 的 query 里多了一个 `response-content-disposition` 参数。

## 三、前端对接修改（怎么改）

### 3.1 下载 — 必须用 `download_url`，且不要在当前标签页导航

```js
// ✅ 正确：新标签页打开，当前页面不受影响，下载文件名与上传一致
function downloadFile(url) {
  window.open(url, '_blank')
}
```

```html
<!-- ✅ 正确：a 标签加 target="_blank" -->
<a :href="item.download_url" target="_blank" rel="noopener">下载</a>
```

**千万不要这样写：**

```js
// ❌ 错误：当前标签页导航到附件 URL → 页面跳转一下又回原页，体验差
window.location.href = downloadUrl

// ❌ 错误：a 标签不带 target → 默认当前页打开，同上
// <a :href="item.download_url">下载</a>
```

### 3.2 预览 — 用 `oss_url`，同样用新标签页

```html
<!-- ✅ 在线预览 PDF：新标签页打开，浏览器内联渲染，不会触发下载 -->
<a :href="item.oss_url" target="_blank" rel="noopener">预览</a>
```

```js
// ✅ 或
window.open(item.oss_url, '_blank')
```

**不要用 `download_url` 做预览**——它带了 attachment，新标签页打开也会直接下载而不是预览。

### 3.3 语义对照速查表

| 场景 | 用哪个字段 | 新标签页打开？ |
|------|-----------|---------------|
| 下载文件（文件名 = 原始名） | `download_url` | ✅ 是 |
| 在线预览 PDF / 图片 / 音视频 | `oss_url` | ✅ 是 |
| 两个都不该在当前页导航打开 | — | — |

### 3.4 注意事项

1. **有效期**：`download_url` / `oss_url` 均为 7 天有效。前端若缓存列表 / 详情响应，请勿超过 7 天；点击下载 / 预览时建议**实时拉取最新 URL**。
2. **空值兜底**：当文档没有 OSS 文件（`oss_key` 为空）时，`download_url` / `oss_url` 返回空字符串 `""`，前端要做空值判断，避免 `window.open('')`。
3. **`fetch + blob` 方案**：如果前端想用 `fetch(url) → blob → <a download>` 的方式下载（可以完全避免页面跳转），需要注意 OSS 桶需要配置 **CORS**（`Access-Control-Allow-Origin`），否则跨域 `fetch` 会失败。未配置 CORS 时请用 `window.open(url, '_blank')` 方案。
4. **旧数据兼容**：本次改动不涉及数据库结构变更，存量文档直接生效。

## 四、建议

1. **封装统一工具函数**：把下载 / 预览封装成前端公共工具，一处改动全局生效，避免每个页面各写一套跳转逻辑。

   ```js
   // utils/download.js
   export function downloadFile(url) {
     if (!url) { console.warn('download_url 为空'); return }
     window.open(url, '_blank')
   }
   export function previewFile(url) {
     if (!url) { console.warn('oss_url 为空'); return }
     window.open(url, '_blank')
   }
   ```

2. **下载 / 预览职责分离**：下载一律 `download_url`，预览一律 `oss_url`，不要把两者混用（用错会导致"预览变下载"或"下载名不对"）。

3. **不要依赖 `oss_key` 拼 URL**：OSS 对象名是 UUID，前端任何时候都不要用 `oss_key` 或自行拼接的 URL 做下载 / 预览，一律使用后端返回的 `download_url` / `oss_url`。

4. **后续可优化项（非本次范围）**：若前端希望"点击下载不弹出新标签页闪一下"，可由后端再提供一个流式下载接口（后端拉 OSS 字节流返回，前端用 `blob` 保存），但需要额外开发，本期不做。
