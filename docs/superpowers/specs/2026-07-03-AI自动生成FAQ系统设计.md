# AI 自动生成 FAQ 系统设计

## 概述

系统定期（每周）分析问答日志，自动提取高频问题，聚类合并相似问题，经 LLM 生成标准化答案后进入草稿状态，由管理员审核发布。同时提供「热点问题广场」—— 展示近期热门提问趋势。

---

## 一、功能范围

| 功能 | 说明 | 复杂度 |
|------|------|--------|
| **热点问题广场** | 智能问答主界面展示「大家都在问」列表，实时统计近期高频问题 | 低 |
| **FAQ 知识沉淀** | AI 自动提取 → 聚类 → 生成 → 审核 → 发布的标准问答库 | 高 |
| **FAQ 管理后台** | 管理员审核、编辑、发布/驳回 FAQ 草稿 | 中 |
| **前端 API** | FAQ 列表、分类、详情接口供前端消费 | 中 |

## 二、数据模型

### FAQCategory — FAQ 分类

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | AutoField | PK | 主键 |
| `name` | CharField(100) | NOT NULL | 分类名称（如"选课相关"、"账号问题"） |
| `icon` | CharField(50) | NULLABLE | 图标标识 |
| `sort_order` | IntegerField | DEFAULT 0 | 排序号 |
| `created_at` | DateTimeField | AUTO | 创建时间 |

### FAQItem — FAQ 条目

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | AutoField | PK | 主键 |
| `question` | CharField(500) | NOT NULL | 标准化问题（LLM 从多个相似问法提炼） |
| `answer` | TextField | NOT NULL | 标准答案（LLM 生成 + 人工可编辑） |
| `category` | FK → FAQCategory | NULLABLE | 所属分类 |
| `college` | FK → College | NULLABLE | **NULL=全局FAQ；非NULL=学院专属** |
| `tags` | JSONField | DEFAULT [] | 关键词标签，用于搜索和聚类 |
| `status` | CharField(20) | DEFAULT 'draft' | `draft` / `published` / `rejected` |
| `frequency` | FloatField | DEFAULT 0 | 该问题占比(%)，如 2.5 |
| `variant_count` | IntegerField | DEFAULT 0 | 同一问题的相似变体合并数量 |
| `source_period_start` | DateTimeField | NULLABLE | 分析周期起始时间 |
| `source_period_end` | DateTimeField | NULLABLE | 分析周期结束时间 |
| `related_doc_ids` | JSONField | DEFAULT [] | 关联知识库文档 ID 列表 |
| `reviewed_by` | FK → User | NULLABLE | 审核人 |
| `reviewed_at` | DateTimeField | NULLABLE | 审核时间 |
| `created_at` | DateTimeField | AUTO | 创建时间 |
| `updated_at` | DateTimeField | AUTO | 更新时间 |

### FAQGenerationLog — 生成日志（内部追踪）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | AutoField | PK | 主键 |
| `status` | CharField(20) | NOT NULL | `running` / `completed` / `failed` |
| `total_questions` | IntegerField | DEFAULT 0 | 本轮采集的总问题数 |
| `clusters_found` | IntegerField | DEFAULT 0 | 聚类后簇数量 |
| `drafts_generated` | IntegerField | DEFAULT 0 | 生成的草稿数 |
| `error_message` | TextField | NULLABLE | 失败原因 |
| `started_at` | DateTimeField | AUTO | 开始时间 |
| `completed_at` | DateTimeField | NULLABLE | 完成时间 |

## 三、AI 提取管道流程

### 整体流程

```
Celery Beat 触发（每周一 03:00）
         │
         ▼
┌─────────────────────┐
│ 阶段1：日志采集      │   查 ChatMessage（role='user'）近一周记录
│       ↓             │   去重 + 排除已提取话题
│ 阶段2：向量聚类      │   DeepSeek Embedding → 余弦相似度
│       ↓             │   阈值 0.85 合并相似问题
│ 阶段3：比例筛选      │   计算占比 → 过滤 > 0.5%
│       ↓             │   Top 20
│ 阶段4：LLM 生成      │   对每个簇：
│                     │   ① 归纳标准化问题
│                     │   ② 生成标准答案
│                     │   ③ 提取标签
│                     │   ④ 判断学院归属和分类
└─────────┬───────────┘
          │
          ▼
    FAQItem (status='draft')  → 等待管理员审核
```

### 阶段详细说明

#### 阶段1：日志采集
- 查询 `ChatMessage` 表 `role='user'`，`created_at` 在最近 7 天内
- 排除本轮已提取过的文本（精确去重）
- 与已有 `FAQItem` 的问题做向量相似度比较，相似度 >0.9 的直接跳过（避免重复提取）

#### 阶段2：向量聚类
- 调用 `utils/llm.py` 的 `embed()` 方法获取每个问题的嵌入向量
- 计算两两余弦相似度
- 相似度 ≥0.85 合并为同一问题簇
- 输出：`List[Cluster]`，每个簇包含若干文本变体

#### 阶段3：比例筛选
- 统计该周总提问数 `total`
- 计算每个簇占比 = `cluster.size / total * 100`
- 过滤保留占比 > 0.5% 的簇
- 取 Top 20 按占比降序排列
- 阈值 `0.5%` 和 `Top 20` 可在 `settings.py` 中配置

#### 阶段4：LLM 生成 FAQ 草稿
- 对每个高频问题簇调用 DeepSeek：
  - 输入：该簇所有问题变体 + 对应 AI 回答
  - 输出：标准化问题、标准答案（200-500字）、标签、学院/分类推断
- 为每个簇创建 `FAQItem`，`status='draft'`
- 记录 `FAQGenerationLog`

## 四、审核工作流

### 流程

```
FAQItem (status='draft')
         │
         ▼
  管理员登录 → 查看审核列表
         │
         ├─ 查看详情（问题、答案、占比、来源）
         │
         ├─ 编辑问题/答案（可选）
         │
         ├─ ✅ 发布 → status='published'
         ├─ ❌ 驳回 → status='rejected'
         └─ 🗑 删除
```

### 权限矩阵

| 操作 | super_admin | college_admin |
|------|-------------|---------------|
| 查看全局 FAQ 草稿 | ✅ | ❌ |
| 查看学院 FAQ 草稿 | ✅ | ✅（仅本学院） |
| 发布全局 FAQ | ✅ | ❌ |
| 发布学院 FAQ | ✅ | ✅（仅本学院） |
| 编辑 FAQ | ✅ | ✅（仅本学院） |
| 驳回/删除 | ✅ | ✅（仅本学院） |

## 五、REST API 设计

### 热点问题（挂载在 chat 应用下）

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/api/chat/hot-questions/` | 获取近期热点问题列表 | 登录用户 |

**参数：** `?days=7`（默认近 7 天），`?top_k=10`（默认 10 条）

**响应：**
```json
[
  {
    "question": "如何重置密码？",
    "count": 45,
    "trend": "up"  // up / down / stable
  }
]
```

### FAQ 公共接口（供前端用户页面调用）

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/api/faq/categories/` | 获取 FAQ 分类列表 | 登录用户 |
| `GET` | `/api/faq/items/` | 获取已发布的 FAQ | 登录用户 |
| `GET` | `/api/faq/items/{id}/` | FAQ 详情 | 登录用户 |

**`GET /api/faq/items/` 自动过滤规则：**
- 返回 `status='published'` 的记录
- 当前用户 `college_id` 匹配 `college_id`（NULL 的全局 FAQ 也可见）
- 按 `frequency` 降序排列

### FAQ 管理接口（供管理员后台调用）

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/api/faq/drafts/` | 待审核草稿列表 | 对应管理员 |
| `GET` | `/api/faq/drafts/{id}/` | 草稿详情 | 对应管理员 |
| `PATCH` | `/api/faq/drafts/{id}/` | 编辑草稿 | 对应管理员 |
| `POST` | `/api/faq/drafts/{id}/publish/` | 发布草稿 | 对应管理员 |
| `POST` | `/api/faq/drafts/{id}/reject/` | 驳回草稿 | 对应管理员 |
| `GET` | `/api/faq/items/` | 全部 FAQ（管理端，含草稿） | 管理员 |
| `DELETE` | `/api/faq/items/{id}/` | 删除 FAQ | 管理员 |

## 六、Celery 任务调度

### 配置

```python
# config/celery.py
app.conf.beat_schedule = {
    'generate-faq-weekly': {
        'task': 'apps.faq.tasks.generate_faq_weekly',
        'schedule': crontab(hour=3, minute=0, day_of_week=1),
    },
}
```

### 防重叠与幂等
- 每次运行前检查 `FAQGenerationLog` 是否有未完成的 `running` 状态记录
- 已生成的草稿在下次运行时通过向量相似度比对排除
- 失败时有 `max_retries=2` 重试机制
