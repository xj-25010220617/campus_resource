# 前端对接接口文档 —— 首页公开统计与看板权限拆分

日期：2026-09-02
范围：后端（campus_resource / backend）+ 前端（vue-file-system）同步改动
文档性质：问题情况说明 + 前端对接规范

---

## 一、问题情况

### 1. 背景

原 `/api/admin/logs/dashboard/` 接口（超管日志看板聚合）此前被直接复用于**首页游客可见的「平台数据概览」**，权限为 `AllowAny`。经审查发现以下问题：

| # | 问题 | 危害 |
|---|---|---|
| 1 | 接口返回超聚合之外的明细：`by_college`（学院名排行）、`top_operators`（操作人用户名排行）、`by_type/by_hour/by_feedback` 等 | 任何游客 curl 即可获取学院粒度、后台操作人排行等敏感信息，与 docstring「不包含个人可识别信息」相悖 |
| 2 | 每块失败时 `{'error': str(原始异常)}` 直接进入 AllowAny 响应 | login 块因 MySQL 时区表缺失，把数据库异常原文吐给了匿名访客 |
| 3 | 首页标签与实际数据语义不符：`访问次数 = OperationLog 流水`（管理端增删改审计，非页面 PV）；`资料总数 = UploadLog 上传流水条数`（含失败/已删记录，与真实资料数漂移）；`用户总数 = 全表`（含管理员） | 对外口径失真 |
| 4 | 数据库时区表未安装，login 块区间统计抛错 | 登录次数恒 0 / 管理端卡片持续报错 |

### 2. 产品决策（2026-09-02）

- **接口拆分**：首页公开展示新建独立公开接口；原看板接口收回为**超管专用**。
- **公开六项指标**（去掉了不存在的「访问次数/PV」，保留存储总量）：
  1. 用户总数 —— `role='user'` 的师生账号数（**不含管理员**）
  2. 存储总量 —— 全部已上传资料占用字节 `Sum(KnowledgeDoc.file_size)`
  3. 资料总数 —— `KnowledgeDoc` 全表计数（**已上传即算**，删除随行消失）
  4. 查询总数 —— `QueryLog` 累计（AI 问答次数）
  5. 敏感拦截 —— `SensitiveLog` 累计（命中敏感词）
  6. 登录次数 —— `LoginLog` 累计
- 公开接口**不含**任何学院 / 操作人 / 明细 / 错误原文。

## 二、后端变更清单

### 1. 新增公开接口

```
GET /api/platform/stats/
```

- 权限：`AllowAny`，且 `authentication_classes = []`（完全不认证——即使请求头携带过期/伪造 Token 也不影响，始终公开）
- 参数：无；固定全量累计口径（与 period 无关）
- 缓存：服务端 120s（Django cache）
- 失败约定：单项计算失败 → 该项为 `null`（其余项照常）；整库不可用（六项全 null）→ HTTP **503**（不缓存）

**响应 200（示例）：**

```json
{
  "users": 1826,
  "storage_bytes": 5368709120,
  "docs": 3421,
  "queries": 20934,
  "sensitive_blocks": 17,
  "logins": 12877
}
```

| 字段 | 类型 | 对外含义 | 口径 |
|---|---|---|---|
| `users` | int / null | 用户总数 | `User.role='user'` 计数，不含管理员 |
| `storage_bytes` | int / null | 存储总量 | `Sum(KnowledgeDoc.file_size)`，**单位字节**，前端自行换算（KB/MB/GB/TB） |
| `docs` | int / null | 资料总数 | `KnowledgeDoc.objects.count()`（全部已上传资料） |
| `queries` | int / null | 查询总数 | `QueryLog` 累计 |
| `sensitive_blocks` | int / null | 敏感拦截 | `SensitiveLog` 累计 |
| `logins` | int / null | 登录次数 | `LoginLog` 累计 |

**错误：** `503`（空 body）= 后端统计暂不可用，前端展示「统计数据加载失败」错误态即可，无需解析。

涉及后端文件：
- `backend/apps/admin_panel/services/dashboard.py`：新增 `compute_public_stats()`（六项口径 + 逐项隔离）
- `backend/apps/admin_panel/views.py`：新增 `PublicStatsView`
- `backend/apps/admin_panel/platform_urls.py`：路由 `stats/`（新建）
- `backend/config/urls.py`：挂载 `path('api/platform/', include('apps.admin_panel.platform_urls'))`

### 2. 原看板接口权限收紧

```
GET /api/admin/logs/dashboard/?period=day|week|month|all
```

- 权限变更：`AllowAny` → **`IsAuthenticated + IsSuperAdmin`**
- **响应结构不变**（全字段保留：`period/start_at/end_at/totals/blocks`，含各块 `by_*`、`top_operators`、`total_size`、`avg_response_ms`、`like_rate`、`success_count`、`fail_count`），仅超管可见
- 涉及文件：`backend/apps/admin_panel/views.py`（`LogsDashboardView.permission_classes`）

## 三、前端必须同步的改动（已落地在 vue-file-system）

> 两处改动必须与后端**同批发布**，否则会出现：管理端 401（token 被白名单剥掉）或首页取数失败。

### 1. `src/api/request.ts` —— 公开接口白名单

- **移除** `'/admin/logs/dashboard/'`：该接口现要求超管 Token，必须放行携带 Token。
- **新增** `'/platform/stats/'`：公开接口不携带 Token（防止本地残留的过期 Token 被 DRF 先拦截）。

### 2. `src/views/home/Introduction.vue` —— 首页「平台数据概览」

- 请求地址：`GET /admin/logs/dashboard/?period=all` → **`GET /platform/stats/`**（无参数）
- 数据映射（旧 → 新）：

| 首页指标 | 旧字段 | 新字段 |
|---|---|---|
| 用户总数 | `totals.users`（含管理员） | `users`（仅 role=user） |
| 存储总量 | `totals.upload_total_size`（上传流水累计） | `storage_bytes`（当前已收录资料占用，字节） |
| 资料总数 | `blocks.upload.total`（上传流水条数） | `docs`（全部已上传资料数） |
| 查询总数 | `blocks.query.total` | `queries` |
| 敏感拦截 | `blocks.sensitive.total` | `sensitive_blocks` |
| 登录次数 | `blocks.login.total`（时区 bug 恒 0） | `logins` |
| ~~访问次数~~ | ~~`blocks.operation.total`（实为后台操作日志）~~ | **移除该项** |

- 响应体扁平化后，去掉原 `DashboardBlock/DashboardResponse/ok()` 逐块容错逻辑，新增 `PublicStats` 接口。
- 界面排版：存储总量仍为主打大数字（`stats[1]`），次级网格由 6 项减为 5 项（`v-for="i in [0, 2, 3, 4, 5]"`）；右上角「统计区间」文案改为「全平台累计」。

### 3. `src/views/admin/LogView.vue` —— 管理端日志页「概览」

- **无需改动**：仍请求 `/admin/logs/dashboard/`，token 由 `request.ts` 恢复携带后自动满足超管权限；响应结构不变，渲染逻辑原样可用。

## 四、遗留运维动作（部署前必须完成）

### 1. 导入 MySQL 时区表（修复 login 块）

不执行则公开接口「登录次数」恒为 0、管理端「登录」卡片持续「数据获取失败」。

服务器执行其一：

```bash
# 方式 A（有 MySQL root 权限）
mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -u root -p mysql

# 方式 B（宝塔面板）：数据库 → 选择 mysql 库 → 导入
#    将 /usr/share/zoneinfo 用 mysql_tzinfo_to_sql 生成的 sql 导入
```

验证：

```sql
SELECT CONVERT_TZ('2026-01-01 00:00:00', 'UTC', 'Asia/Shanghai');
```

返回非 NULL 即成功。

### 2. 后端部署

```bash
cd /www/wwwroot/campus_resource/backend
git pull
venv/bin/python manage.py check
# 重启 gunicorn（沿用 kill master + nohup 启动 / bt_pym）
```

### 3. 前端部署

`vue-file-system` 两个文件随下一版本发布（与后端同批）。
