## 二、接口详情

### 2.1 语音问答

```
POST /api/chat/voice-ask/
Content-Type: multipart/form-data
```

**功能**：接收音频文件 → FunASR 语音转文字 → RAG 检索 → LLM 流式 SSE 回答。整体流程与文字问答（`POST /api/chat/ask/`）一致，区别在于输入从文字变成了音频。

**权限**：已登录用户（`IsAuthenticated`）

**请求参数**（form-data）：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `audio_file` | file | 是 | 音频文件，支持 WAV / MP3 / M4A / AAC / OGG / FLAC / PCM，最大 10MB |
| `conversation_id` | integer | 否 | 会话 ID，不传则自动创建新会话 |

**响应**：SSE 流式（`text/event-stream`）

**请求示例**（curl）：

```bash
curl -X POST http://localhost:8000/api/chat/voice-ask/ \
  -H "Authorization: Bearer <your_token>" \
  -F "audio_file=@recording.wav" \
  -F "conversation_id=3"
```

## 三、SSE 事件流详解

### 3.1 响应头

```
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
X-Accel-Buffering: no
X-Message-Id: <query_log_id>   # 查询日志ID，可用于后续反馈
```

> `X-Message-Id` 返回的是 `QueryLog` 表的 `id`，可用于后续调用 `POST /api/chat/message/{id}/rate/` 做满意度反馈。

### 3.2 事件列表

客户端需要监听以下 5 种 SSE 事件：

| 事件名 | 触发时机 | data 示例 | 说明 |
|--------|----------|-----------|------|
| `msg` | LLM 逐 token 输出时 | `{"content": "这是回答的..."}` | 回答文本片段，累加即为完整回答 |
| `done` | LLM 生成完毕 | `{"message_id": 123}` | 流结束标记，附 AI 消息 ID |
| `references` | 流结束后（普通用户） | `{"count": 3, "summary": "参考了3份文档"}` | 引用摘要，不含文档详情 |
| `references_detail` | 流结束后（admin/super_admin） | `[{doc_id, doc_title, page, score, content_snippet, download_url}]` | 引用详情列表，含下载链接 |
| `error` | 任何阶段异常 | `{"message": "回答生成失败: ...", "code": "LLM_ERROR"}` | 错误信息，code 为错误码 |

### 3.3 SSE 数据格式

每条 SSE 事件格式：

```
event: {事件名}
data: {JSON字符串}

```

（两条 `\n` 结尾，这是 SSE 标准格式）

### 3.4 完整 SSE 流转示例

```
event: msg
data: {"content": "这"}

event: msg
data: {"content": "是一"}

event: msg
data: {"content": "段语"}

event: msg
data: {"content": "音回"}

event: msg
data: {"content": "答的"}

event: msg
data: {"content": "内容..."}

event: done
data: {"message_id": 456}

event: references
data: {"count": 2, "summary": "参考了2份文档"}
```

### 3.5 references_detail 详情（admin / super_admin）

当请求用户角色为 `admin` 或 `super_admin` 时，`references` 事件被替换为 `references_detail`：

```json
[
  {
    "doc_id": 10,
    "doc_title": "数据结构课件.pdf",
    "page": 3,
    "score": 0.92,
    "content_snippet": "栈是一种后进先出（LIFO）的数据结构...",
    "download_url": "https://oss.example.com/..."
  },
  {
    "doc_id": 15,
    "doc_title": "算法笔记.docx",
    "page": 1,
    "score": 0.78,
    "content_snippet": "递归算法的时间复杂度分析...",
    "download_url": "https://oss.example.com/..."
  }
]
```

> `download_url` 有效期 300 秒（5分钟），由 OSS 签名生成。

## 四、错误处理

### 4.1 错误响应一览

| HTTP 状态码 | code | detail | 原因 |
|-------------|------|--------|------|
| 400 | `FILE_TOO_LARGE` | 音频文件不能超过 10MB | 文件大小超限 |
| 400 | `validation_error` | 各字段校验错误信息 | 请求参数校验失败 |
| 500 | `ASR_FAILED` | 语音识别失败，请确认音频清晰且包含中文语音 | FunASR 模型未加载或识别结果为空 |
| 500 | `ASR_FAILED` | 语音识别失败: {具体错误} | FunASR 模型加载报错（如依赖缺失） |
| 500 | `LLM_ERROR` | 回答生成失败: {具体错误} | LLM 流式输出异常 |

### 4.2 前端错误处理建议

```javascript
const eventSource = new EventSource(`/api/chat/voice-ask/`, {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${token}` },
  body: formData, // FormData，含 audio_file
});

// 注意：EventSource 不支持 POST body，需用 fetch + ReadableStream
const response = await fetch('/api/chat/voice-ask/', {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${token}` },
  body: formData,
});

const reader = response.body.getReader();
const decoder = new TextDecoder();
let done = false;
let fullText = '';

while (!done) {
  const { value, done: d } = await reader.read();
  done = d;
  if (!value) continue;

  const text = decoder.decode(value, { stream: !done });
  // text 可能是多条 SSE 事件粘在一起，需要按行解析
  parseSSELines(text, {
    onMsg: (chunk) => { fullText += chunk; updateUI(fullText); },
    onDone: (data) => { console.log('message_id:', data.message_id); },
    onReferences: (data) => { showReferences(data); },
    onError: (data) => { showError(data.message); },
  });
}
```

SSE 行解析辅助函数：

```javascript
function parseSSELines(text, callbacks) {
  const lines = text.split('\n');
  let eventName = '';
  let dataBuffer = '';

  for (const line of lines) {
    if (line.startsWith('event: ')) {
      eventName = line.slice(7).trim();
    } else if (line.startsWith('data: ')) {
      dataBuffer = line.slice(6).trim();
    } else if (line === '') {
      // 空行 = 一条事件结束
      if (eventName && dataBuffer) {
        const data = JSON.parse(dataBuffer);
        callbacks[`on${capitalize(eventName)}`]?.(data);
      }
      eventName = '';
      dataBuffer = '';
    }
  }
}

function capitalize(s) {
  return s.charAt(0).toUpperCase() + s.slice(1);
}
```

## 五、底层技术说明

### 5.1 语音识别（ASR）

- **模型**：阿里达摩院 FunASR `paraformer-zh`（中文 paraformer）
- **加载方式**：懒加载 + 单例，首次调用自动下载模型（~300MB）
- **设备**：优先使用 CUDA（GPU），无 GPU 时回退到 CPU
- **音频预处理**：非 WAV 格式（MP3/M4A/AAC/OGG/FLAC 等）自动转码为 16kHz 单声道 WAV
- **识别结果**：仅提取 `text` 字段，去除 SenseVoice 情绪标签（`<|xxx|>` 格式）

### 5.2 后续流程（与文字问答一致）

语音转文字后的后续流程与 `POST /api/chat/ask/` 完全相同：

1. **RAG 检索**：调用 `utils.rag.retrieve()`，根据用户角色（`user`/`admin`/`super_admin`）和学院/部门范围过滤知识库，返回 Top-K 相关文档（`top_k=5`，`score >= 0.7`）
2. **LLM 生成**：调用 `utils.llm.llm_client.chat_stream()`，流式返回逐 token 回答
3. **日志写入**：同时写入 `QueryLog`（记录问题、命中数、响应耗时）和 `ChatMessage`（记录用户消息+AI回答）

### 5.3 QueryLog 关联

每次语音问答都会在 `QueryLog` 表创建一条记录，`X-Message-Id` 响应头即为该记录的 `id`，可用于：

- 后续 `POST /api/chat/message/{id}/rate/` 做满意度反馈
- 在管理后台查询该语音问答的命中情况

## 六、典型调用场景

### 场景1：新建会话（语音提问）

```bash
curl -X POST http://localhost:8000/api/chat/voice-ask/ \
  -H "Authorization: Bearer <token>" \
  -F "audio_file=@question.m4a"
```

返回 SSE 流，前端组装 `msg` 事件内容即为 AI 回答，`done` 事件中含 `message_id`。

### 场景2：继续当前会话（语音追问）

```bash
curl -X POST http://localhost:8000/api/chat/voice-ask/ \
  -H "Authorization: Bearer <token>" \
  -F "audio_file=@followup.wav" \
  -F "conversation_id=3"
```

RAG 检索时会将对话历史作为上下文一并发送（由 `AskView` 已有逻辑处理）。

### 场景3：管理员查看引用详情

admin / super_admin 角色收到的 SSE 事件是 `references_detail`（而非普通用户的 `references`），可直接拿到 `doc_id` 和 `download_url`，无需额外调接口。

## 七、常见问题

| 问题 | 解答 |
|------|------|
| 音频格式有哪些？ | 支持 WAV / MP3 / M4A / AAC / OGG / FLAC / PCM，底层统一转为 16kHz WAV 再识别 |
| 语音识别失败常见原因？ | ① 音频过短（<0.5s）；② 音频质量差；③ 音频中无中文语音；④ FunASR 模型未安装（需 `pip install funasr`） |
| 为什么有时 `error` 事件是 `ASR_FAILED` 但没有具体错误信息？ | `_model_error` 变量在模型加载失败时记录原因；若为 `None` 说明是返回空文本而非异常 |
| 普通用户能否看到引用文档的详情？ | 不能。普通用户收到 `references`（仅 count + summary）；管理员收到 `references_detail`（含下载链接） |
| 如何区分"没找到相关内容"和"语音识别失败"？ | 语音识别失败 → HTTP 500 + `ASR_FAILED`；没找到相关内容 → SSE `references` 返回 `count: 0` |
| SSE 流中断了怎么办？ | 可用 `message_id`（`X-Message-Id` 或 `done` 事件）查到 `QueryLog`，重试时传 `conversation_id` 继续同一会话 |
