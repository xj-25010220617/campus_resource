# 前端对接接口文档 — 文档列表返回真实文件扩展名（2026-09-10）

> **日期**：2026-09-10
> **后端分支**：main
> **认证说明**：所有接口均需要携带 JWT Token，格式：`Authorization: Bearer <token>`
> **本文档面向**：前端对接同学，说明「列表返回的 `file_type` 是类别而非真实格式」的原因、后端新增字段，以及前端如何取用。

## 〇、本次变更清单

| # | 接口 / 数据 | 变更类型 | 说明 |
|---|------------|---------|------|
| 1 | `GET /api/knowledge/docs/`（文档列表） | **字段新增** | 新增 `file_ext`（真实扩展名）、`file_name`（原始文件名） |

## 一、问题背景（现象与根因）

### 1.1 现象

列表里上传了一个 `热门话题分享.pptx`，接口返回的 `file_type` 是 `"ppt"`；上传 `课表.xlsx` 返回 `"xls"`；上传 `照片.jpg` 返回 `"image"`。前端拿不到 `pptx` / `xlsx` / `jpg` 这类**真实格式**，没法做精确的图标映射和"按格式筛选"。

### 1.2 根因

`KnowledgeDoc.file_type` 这一列**存的不是扩展名，是归一化后的「类别」**。模型 `FILE_TYPE_CHOICES` 只有 11 个值：

```
pdf / doc / ppt / xls / image / video / audio / md / txt / html / other
```

所有写入路径都经过 `normalize_file_type()` 归一化：

| 上传的真实扩展名 | 落库的 `file_type` |
|---|---|
| `docx` | `doc` |
| `pptx` | `ppt` |
| `xlsx` / `csv` | `xls` |
| `jpg` / `png` / `gif` / `webp` / `tiff` … | `image` |
| `mp4` / `mov` / `avi` / `mkv` … | `video` |
| `zip` / `rar` / `psd` / `stl` … | `other` |

**真实扩展名只存在于 `file_name` 字段**（上传时原样保存的原始文件名）。

---

## 二、新增字段说明

### 2.1 `file_ext` — 真实扩展名（推荐使用）

| 属性 | 值 |
|---|---|
| 类型 | `string`，小写，不含点号 |
| 是否必返 | 是，**永不为空** |
| 来源 | 从 `file_name` 解析后缀 |

**取值规则**：

1. `file_name` 有合法后缀 → 返回该后缀，如 `pptx`、`docx`、`xlsx`、`jpg`、`mp4`；
2. 后缀明显不是扩展名（如 `会议记录.2026` 的 `2026`）、或 `file_name` 为空（部分爬虫来源的老数据）→ **兜底返回 `file_type` 类别码**（`pdf` / `doc` / `image` …）。

> 即：`file_ext` 一定是「真实格式」，只有在拿不到真实格式时才退化成「类别」，不存在空值，前端无需判空。

### 2.2 `file_name` — 原始文件名

仅列表接口新增（详情接口本来就有）。上传时用户看到的原始文件名，例如 `热门话题分享.pptx`。可用于展示、或前端自行二次解析。

## 四、前端对接建议

| 场景 | 用哪个字段 |
|---|---|
| 文件图标映射（docx 蓝色 / pptx 橙色 …） | **`file_ext`** |
| 文件卡片上显示的格式标签 | **`file_ext`**（可 `toUpperCase()` 展示为 `PPTX`） |
| 已有的类型筛选器（文档 / 图片 / 视频 / 音频） | `file_type`（**不变**，无需改） |
| 展示原始文件名 | `file_name` |

**向后兼容**：老前端不改也不会出错；新前端把图标映射的 key 从 `file_type` 换成 `file_ext` 即可拿到更细的粒度。若仍希望「一组格式共用一个图标」，建议前端自建映射表，例如：

```js
const ICON_BY_EXT = {
  pdf: 'pdf',
  doc: 'word', docx: 'word',
  xls: 'excel', xlsx: 'excel', csv: 'excel',
  ppt: 'ppt', pptx: 'ppt',
  md: 'markdown', txt: 'text', html: 'html',
  jpg: 'image', jpeg: 'image', png: 'image', gif: 'image',
  webp: 'image', bmp: 'image', tiff: 'image', tif: 'image',
  mp3: 'audio', wav: 'audio', // …
  mp4: 'video', mov: 'video', // …
};
// 未命中时兜底用 file_type
const icon = ICON_BY_EXT[doc.file_ext] || doc.file_type || 'other';
```

## 五、其他相关说明

### 5.1 新增上传无需前端改动

转换逻辑完全在后端序列化层完成，**上传/回调接口的请求参数不变**，前端继续按扩展名传 `file_type` 即可（后端照旧归一化落库）。

### 5.2 分页提醒（`page_size` 当前不生效）

后端使用 DRF 默认 `PageNumberPagination`，`PAGE_SIZE=20`，且**未开启 `page_size_query_param`**，因此请求里的 `?page_size=1000` 会被**静默忽略**，实际每页固定 20 条（`count=60` 时会分 3 页）。

需要「一页拿全」或自定义每页条数的话，请后端同学在 `config/settings.py` 的 `REST_FRAMEWORK` 中配置：

```python
'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',
'PAGE_SIZE': 20,
```

并新增分页类启用 `page_size_query_param = 'page_size'` 与 `max_page_size`。当前前端请按 `next` 字段循环翻页取全量。
