# 前端对接接口文档 — 文档标签 + 文件网关联（AI 自动关联）（2026-10-25）

> **日期**：2026-10-25
> **后端分支**：main
> **认证说明**：所有接口均需携带 JWT Token，格式：`Authorization: Bearer <token>`
> **本文档面向**：前端对接同学，说明「上传时人工打标签、文档间 AI 自动关联（文件网）」两块能力的接口用法。

---

## 〇、本次变更清单

| # | 接口 | 变更类型 | 说明 |
|---|------|---------|------|
| 1 | `GET /api/knowledge/tags/` | 新增 | 查询标签词表（全平台共享） |
| 2 | `GET /api/knowledge/docs/{doc_id}/tags/` | 新增 | 查询某文档的标签 |
| 3 | `POST /api/knowledge/docs/{doc_id}/tags/create/` | 新增 | 为文档批量打标签 |
| 4 | `DELETE /api/knowledge/docs/{doc_id}/tags/{tag_id}/delete/` | 新增 | 移除文档上的标签 |
| 5 | `GET /api/knowledge/docs/{doc_id}/relations/` | 新增 | 查询某文档的关联（文件网出边，由 AI 自动生成） |
| 6 | `DELETE /api/knowledge/docs/{doc_id}/relations/{relation_id}/delete/` | 新增 | 删除一条文档关联（软删，管理员修正 AI 误连） |
| 7 | 5 个上传接口 | 入参新增 | 新增可选入参 `tags`（不含 `relations`） |
| 8 | `GET /api/knowledge/docs/{id}/` | 返回字段新增 | 详情新增 `tags`、`relations` 字段 |

> ⚠️ **与上一版的重要变更**：文档关联**不再由用户手动选择**。原 `POST /docs/{doc_id}/relations/create/`（手动建边）与
> `POST /docs/{doc_id}/relations/recommend/`（AI 推荐候选）两个接口已**下线**，上传时的 `relations` 入参也已移除。
> 改为：文档上传成功后，后端**异步调用 AI 自动分析并直接关联**到相关文档（详见第三节）。

## 一、背景与数据模型

**标签（Tag）与关键词（Keyword）是两套独立体系**：

| 维度 | 关键词 keyword | 标签 tag |
|---|---|---|
| 来源 | 上传时手动提供，或 AI 自动提取 | 仅人工打标（AI 不自动生成） |
| 用途 | 提升 AI 检索召回权重 | 浏览/筛选/聚合，不带检索权重 |
| 词表 | 每文档独立（phrase 不跨文档去重） | **全平台共享一套词表**，不存在则自动创建 |

**文档关联（DocRelation）= 文件网的有向边**：`源文档 → 目标文档`，每条边带一个 `relation_type`。
关联边由后端 **AI 自动生成**，用户不参与选择目标文档，也看不到「待选的其他文档列表」。

**关联类型枚举 `relation_type`**：

| 值 | 含义 |
|---|---|
| `prerequisite` | 前置知识 |
| `supplement` | 补充材料 |
| `same_course` | 同课相关 |
| `citation` | 引用来源 |
| `replaces` | 替代/新版 |

## 二、标签接口

### 2.1 查询标签词表

`GET /api/knowledge/tags/`

返回全平台共享的标签词表（软删除的不返回），按创建顺序排列。上传打标签前可先拉此列表做「标签候选/联想」。

**响应**：

```json
[
  { "id": 1, "name": "高等数学", "created_at": "2026-10-22T10:00:00Z" },
  { "id": 2, "name": "数据结构", "created_at": "2026-10-22T10:01:00Z" }
]
```

### 2.2 查询文档标签

`GET /api/knowledge/docs/{doc_id}/tags/`

返回某文档被打上的标签（所有登录用户可查，文档需在可浏览范围内）。

**响应**：

```json
[
  { "id": 11, "tag_id": 1, "tag_name": "高等数学", "created_at": "2026-10-22T10:00:00Z" },
  { "id": 12, "tag_id": 2, "tag_name": "数据结构", "created_at": "2026-10-22T10:02:00Z" }
]
```

### 2.3 批量打标签

`POST /api/knowledge/docs/{doc_id}/tags/create/`

为文档批量打标签。标签名不存在则**自动创建**（写入共享词表）；重复打标幂等（不报错、不重复建关联）。

**请求体**（`Content-Type: application/json`）：

```json
{ "names": ["高等数学", "期中复习", "新标签"] }
```

- `names`：标签名称数组，必填，1~20 个；单个标签名 ≤ 64 字符。

**响应**：

```json
{
  "created": 2,
  "tags": [
    { "id": 11, "tag_id": 1, "tag_name": "高等数学", "created_at": "..." },
    { "id": 12, "tag_id": 2, "tag_name": "数据结构", "created_at": "..." }
  ]
}
```

- `created`：本次**实际新增**的标签关联数量（已存在的不重复计数）。
- `tags`：该文档**当前全部**标签（含历史已打），可直接回显给前端。

**权限**：`super_admin` 可给任意文档打标；其他角色仅能给自己上传的文档打标，否则返回 403。

### 2.4 移除文档标签

`DELETE /api/knowledge/docs/{doc_id}/tags/{tag_id}/delete/`

移除文档上的一个标签（**仅删除关联，不删除标签词条本身**）。

**响应**：

```json
{ "detail": "删除成功" }
```

**权限**：同 2.3。

## 三、文档关联接口（文件网，AI 自动生成）

### 3.1 关联是如何产生的（重要）

用户**不再手动选择关联**。上传文档成功后，后端异步任务 `auto_link_relations_task` 会：

1. 取「上传者可浏览范围内的**公开**文档」作为候选池；
2. 调用 LLM 分析源文档与候选的相似度，挑选最相关的若干篇并判断关联类型；
3. **直接落成 `DocRelation` 边**（写入 `doc_relation` 表）。

因此前端上传后**无需任何关联相关操作**，过几秒轮询/刷新 3.2 的列表接口即可看到自动生成的关联。

> 候选池只含**公开文档**，且严格限定在上传者本人可浏览范围内——AI 不会、也无法把私密文档或越权文档关联进来，
> 用户不会看到任何「别人创建的、自己本不该看的」文档。

### 3.2 查询文档关联

`GET /api/knowledge/docs/{doc_id}/relations/`

返回源文档指向其他文档的**出边**（按创建时间倒序），所有登录用户可查。AI 自动关联落库后即在此返回。

**响应**：

```json
[
  {
    "id": 31,
    "source_doc_id": 128,
    "target_doc_id": 56,
    "target_doc_title": "线性代数讲义",
    "relation_type": "prerequisite",
    "relation_type_name": "前置知识",
    "created_at": "2026-10-22T11:00:00Z"
  }
]
```

### 3.3 删除文档关联

`DELETE /api/knowledge/docs/{doc_id}/relations/{relation_id}/delete/`

删除一条关联边（**软删除**，`is_deleted=1`，保留历史记录）。用于管理员修正 AI 误连。

**响应**：

```json
{ "detail": "删除成功" }
```

**权限**：`super_admin` 可删除任意文档的关联；其他角色仅能删除自己上传文档的关联，否则返回 403。

## 四、上传接口新增入参

以下 5 个上传接口在原有参数基础上，新增一个**可选**入参 `tags`（**不再接受 `relations`**）：

| 上传接口 | 路径 |
|---|---|
| 单文件上传 | `POST /api/knowledge/upload/file/` |
| 批量上传 | `POST /api/knowledge/upload/batch/` |
| 文本录入 | `POST /api/knowledge/upload/text/` |
| OSS 直传回调 | `POST /api/knowledge/upload/callback/` |
| 分片合并上传 | `POST /api/knowledge/upload/chunk/merge/` |

**新增入参**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `tags` | `string[]` | 否 | 标签名称列表（与关键词分离，人工打标）。不传则不打标 |

**JSON 请求示例**（文本录入 / OSS 回调）：

```json
{
  "content": "……",
  "visibility": "public",
  "keywords": ["微积分", "高数"],
  "tags": ["高等数学", "期中复习"]
}
```

**multipart/form-data（文件直传/批量）说明**：

- `tags` 与 `keywords` 一样，兼容三种传法：重复字段 `tags=a&tags=b`、JSON 字符串 `tags='["a","b"]'`、数组命名字段 `tags[]=a&tags[]=b`。

> 上传响应**不变**（仍是原来的 `id/status/title/...` 字段），标签不单独回显；前端如需展示可随后调 2.2 或直接读详情（见第五节）。
> 关联则由后端异步自动生成，前端无需在请求中提供。

## 五、文档详情新增返回字段

`GET /api/knowledge/docs/{id}/` 的响应新增两个只读字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tags` | `object[]` | 文档标签，元素 `{id, tag_id, tag_name, created_at}`，结构同 2.2 |
| `relations` | `object[]` | 文档对外关联（出边，AI 自动生成），元素结构同 3.2 |

**响应示例（节选）**：

```json
{
  "id": 128,
  "title": "微积分讲义",
  "tags": [
    { "id": 11, "tag_id": 1, "tag_name": "高等数学", "created_at": "..." }
  ],
  "relations": [
    {
      "id": 31,
      "source_doc_id": 128,
      "target_doc_id": 56,
      "target_doc_title": "线性代数讲义",
      "relation_type": "prerequisite",
      "relation_type_name": "前置知识",
      "created_at": "..."
    }
  ]
}
```

> 列表接口（`GET /api/knowledge/docs/`）**不含** `tags`/`relations`（避免列表页拖慢），详情页才带。

## 六、前端对接建议（推荐交互流程）

**上传打标**：

1. 上传前可先 `GET /tags/` 拉词表做标签联想/候选；
2. 上传时把用户勾选的标签放进 `tags`（一次请求完成打标；**不需要**再传关联）；
3. 上传成功后，关联由后端异步 AI 自动生成，前端可：
   - 详情页进入时直接读 `GET /docs/{id}/` 的 `tags` / `relations` 字段渲染标签与「文件网」图谱；
   - 或单独调 `GET /docs/{id}/relations/` 轮询，数秒内即可看到自动生成的关联边。
4. 若发现 AI 关联错误，管理员可调 `DELETE /docs/{id}/relations/{relation_id}/delete/` 撤边。

**关联展示兜底**（可选）：

```js
const detail = await getDocDetail(docId);
if (!detail.relations.length) {
  // AI 未生成关联（如无公开相关文档 / LLM 暂不可用）：直接不展示关联区即可，
  // 不提供手动建边入口（关联目标不应暴露给用户挑选）。
}
```

## 七、权限与错误码说明

**统一返回格式**（沿用项目约定）：

- 成功：直接返回数据，或 `{"detail": "操作成功"}`；
- 失败：`{"detail": "错误描述", "code": "错误码"}`。

**权限矩阵**：

| 接口 | super_admin | admin（学院管理员） | user（普通用户） |
|---|---|---|---|
| 查询标签词表 / 文档标签 / 文档关联 | ✅ | ✅ | ✅（仅可浏览范围内） |
| 打标签 / 删标签 | ✅ 任意文档 | ✅ 仅本人上传文档 | ❌ |
| 删关联 | ✅ 任意文档 | ✅ 仅本人上传文档 | ❌ |

**常见错误**：

| 场景 | 返回 |
|---|---|
| 给他人文档打标/删关联 | `403`，`detail: "只能给自己上传的文档…"` |
| 标签名列表为空 | `400`（`names` 校验失败） |

## 八、其他说明

- **标签与关键词完全解耦**：标签不影响 AI 检索权重，关键词不影响标签列表；两套接口/字段独立读写。
- **标签共享词表**：A 同学新建的标签，B 同学上传时可复用（`GET /tags/` 能看到）；标签名全局唯一。
- **关联为有向边**：A→B 与 B→A 是两条独立关系，AI 可分别生成。
- **关联由 AI 自动生成**：候选池为「上传者可浏览范围内的公开文档」最近 100 条，单次最多关联 10 条；无相关公开文档或 LLM 不可用时不会生成关联（前端无需兜底手动建边）。
- **关联异步生成**：上传响应返回时不保证关联已生成，前端以列表/详情接口的实际数据为准。
- **向后兼容**：新增字段不影响老前端；下线的 `relations/create`、`relations/recommend` 接口与上传 `relations` 入参，老前端若在调用需同步去掉，否则返回 404 / 被忽略。
