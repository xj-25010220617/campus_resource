## 一、背景与数据模型

**标签（Tag）与关键词（Keyword）是两套独立体系**：

| 维度 | 关键词 keyword | 标签 tag |
|---|---|---|
| 来源 | 上传时手动提供，或 AI 自动提取 | 仅人工打标（AI 不自动生成） |
| 用途 | 提升 AI 检索召回权重 | 浏览/筛选/聚合，不带检索权重 |
| 词表 | 每文档独立 | **全平台共享一套词表**，不存在则自动创建 |

**标签的价值在「浏览/筛选/聚合」**：它应该出现在列表卡片、侧边栏、详情页，并支持点击筛选——本文档第二、三节就是围绕这个闭环。

## 二、标签接口

### 2.1 查询标签词表（含文档数）

`GET /api/knowledge/tags/`

返回全平台共享的标签词表（软删除的不返回），按创建顺序排列。每项带 `doc_count`。

**响应**：

```json
[
  { "id": 1, "name": "高等数学", "created_at": "2026-10-22T10:00:00Z", "doc_count": 12 },
  { "id": 2, "name": "数据结构", "created_at": "2026-10-22T10:01:00Z", "doc_count": 7 }
]
```

- `doc_count`：**当前登录用户可浏览范围内**打了该标签的文档数（随权限变化，普通用户看到的数是自己可见的文档数）。前端用它渲染「标签云/侧边栏」的计数，点击即触发 3.1 的筛选。

### 2.2 查询文档标签

`GET /api/knowledge/docs/{doc_id}/tags/`

**响应**：

```json
[
  { "id": 11, "tag_id": 1, "tag_name": "高等数学", "created_at": "2026-10-22T10:00:00Z" }
]
```

### 2.3 批量打标签

`POST /api/knowledge/docs/{doc_id}/tags/create/`

**请求体**：`{ "names": ["高等数学", "期中复习"] }`（1~20 个，单个 ≤64 字符，不存在则自动创建，重复幂等）

**响应**：

```json
{
  "created": 2,
  "tags": [ { "id": 11, "tag_id": 1, "tag_name": "高等数学", "created_at": "..." } ]
}
```

**权限**：`super_admin` 可给任意文档打标；其他角色仅能给自己上传的文档打标。

### 2.4 移除文档标签

`DELETE /api/knowledge/docs/{doc_id}/tags/{tag_id}/delete/`

移除文档上的一个标签（仅删关联，不删词条）。返回 `{"detail": "删除成功"}`。权限同 2.3。

### 2.5 重命名标签（词表管理）

`POST /api/knowledge/tags/{tag_id}/rename/`

**请求体**：`{ "name": "高数" }`

**响应**：`{ "id": 1, "name": "高数", "created_at": "..." }`

- 新名称 ≤64 字符、全局唯一；重名返回 400（提示改用合并）。

**权限**：仅 `super_admin`（标签是全平台共享词表，重命名影响所有人）。

### 2.6 合并重复标签（词表管理）

`POST /api/knowledge/tags/merge/`

**请求体**：`{ "source_tag_id": 2, "target_tag_id": 1 }`

- `source_tag_id`：被合并的源标签（合并后软删）；`target_tag_id`：保留的目标标签。
- 行为：源标签的所有文档关联改指向目标标签（文档已有目标标签时跳过，避免重复关联），随后软删源词条。

**响应**：`{ "detail": "合并成功", "moved": 5, "tag": { "id": 1, "name": "高等数学", ... } }`

- `moved`：本次实际迁移的文档关联数。

**权限**：仅 `super_admin`。

### 2.7 软删标签词条（词表管理）

`DELETE /api/knowledge/tags/{tag_id}/delete/`

软删标签词条（`is_deleted=1`），并移除该标签在全部文档上的关联。返回 `{"detail": "删除成功"}`。

**权限**：仅 `super_admin`。

## 三、按标签筛选文档

`GET /api/knowledge/docs/?tag_id=1` 或 `GET /api/knowledge/docs/?tag=高等数学`

在文档列表接口新增两个筛选参数（可与其他参数 `college_id`、`file_type` 等组合）：

| 参数 | 类型 | 说明 |
|---|---|---|
| `tag_id` | `int` | 按标签 ID 精确筛选 |
| `tag` | `str` | 按标签名称精确筛选 |

> 前端「点标签徽章 / 点侧边栏标签」→ 跳转到带 `tag_id`（或 `tag`）的列表页，即完成「按标签聚合」。

### 3.1 列表项新增 `tags` 字段

`GET /api/knowledge/docs/` 的每项新增 `tags` 字段（轻量，只回显 id + name，供列表卡片右上角渲染标签徽章）：

```json
{
  "id": 128,
  "title": "微积分讲义",
  "file_type": "pdf",
  "tags": [ { "id": 1, "name": "高等数学" }, { "id": 3, "name": "期中复习" } ]
}
```

> 列表用 `prefetch_related` 预取标签，不会产生 N+1 拖慢列表。

## 四、文档关联接口（文件网，AI 自动生成）

### 4.1 关联如何产生

文档上传成功后，后端异步任务自动调用 AI，从「上传者可浏览范围内的**公开**文档」中挑选相关项并**直接落成关联边**。用户不参与选择、也看不到他人文档。

### 4.2 查询文档关联

`GET /api/knowledge/docs/{doc_id}/relations/`

```json
[
  {
    "id": 31, "source_doc_id": 128, "target_doc_id": 56,
    "target_doc_title": "线性代数讲义",
    "relation_type": "prerequisite", "relation_type_name": "前置知识",
    "created_at": "2026-10-22T11:00:00Z"
  }
]
```

`relation_type` 枚举：`prerequisite`（前置知识）/ `supplement`（补充材料）/ `same_course`（同课相关）/ `citation`（引用来源）/ `replaces`（替代/新版）。

### 4.3 删除文档关联

`DELETE /api/knowledge/docs/{doc_id}/relations/{relation_id}/delete/`（软删，管理员修正 AI 误连）。权限：超管任意文档，其他角色仅本人上传文档。

## 五、上传接口入参

5 个上传接口（单文件 / 批量 / 文本录入 / OSS 回调 / 分片合并）新增可选入参 `tags`：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `tags` | `string[]` | 否 | 标签名称列表（与关键词分离，人工打标）。不传则不打标 |

```json
{ "content": "……", "visibility": "public", "keywords": ["微积分"], "tags": ["高等数学", "期中复习"] }
```

> 上传响应不变；关联由后端异步自动生成，前端无需在请求中提供。

## 六、文档详情 / 列表字段汇总

| 接口 | 标签字段 | 关联字段 |
|---|---|---|
| `GET /docs/`（列表） | `tags`（轻量 `{id,name}`） | — |
| `GET /docs/{id}/`（详情） | `tags`（`{id,tag_id,tag_name,created_at}`） | `relations`（出边） |

## 七、前端对接建议

1. 上传前 `GET /tags/` 拉词表做联想/候选（现在带 `doc_count`，也能直接做侧边栏）；
2. 上传时把用户勾选的标签放进 `tags`；
3. 列表页每个文档卡片右上角渲染 `tags` 徽章，点击徽章 → 跳 `GET /docs/?tag_id=xxx`；
4. 侧边栏/标签云用 `GET /tags/` 的 `id/name/doc_count` 渲染，点击 → 跳 `GET /docs/?tag_id=xxx`；
5. 详情页 `tags` 做成可点击，同样跳筛选列表；
6. 管理员在后台可对词表做重命名 / 合并 / 软删（2.5~2.7）。

## 八、权限与错误码

**统一返回格式**：成功直接返回数据或 `{"detail": "..."}`；失败 `{"detail": "...", "code": "..."}`。

| 能力 | super_admin | admin（学院管理员） | user（普通用户） |
|---|---|---|---|
| 查词表 / 文档标签 / 关联 | ✅ | ✅ | ✅（仅可浏览范围） |
| 打标签 / 删标签 | ✅ 任意文档 | ✅ 仅本人上传 | ❌ |
| 删关联 | ✅ 任意文档 | ✅ 仅本人上传 | ❌ |
| 词表管理（重命名/合并/软删） | ✅ | ❌ | ❌ |

**常见错误**：

| 场景 | 返回 |
|---|---|
| 给他人文档打标/删关联 | `403` |
| 标签名重名（重命名） | `400`，`detail: 标签「xx」已存在…` |
| 词表管理非超管 | `403`，`detail: 仅超级管理员可管理标签词表` |

## 九、其他说明

- **标签与关键词完全解耦**：标签不影响检索权重，关键词不影响标签列表。
- **标签共享词表**：全平台共享、名称全局唯一；`doc_count` 按当前用户可浏览范围计算。
- **词表管理为全局操作**：重命名/合并/软删影响全平台，故仅超管可用。
- **关联由 AI 自动生成**：候选池为上传者可浏览范围内的公开文档最近 100 条，单次最多 10 条；无相关公开文档或 LLM 不可用时不会生成关联。
- **向后兼容**：全部为新增/增强字段与接口，未删除旧字段。
