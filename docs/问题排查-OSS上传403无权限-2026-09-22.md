# 问题排查：OSS 上传报 403 AccessDenied（bucket acl 无权限）

> **适用对象**：后端开发 / 部署同学
> **影响范围**：所有走 `put_object` 直传 OSS 的功能——网页上传、批量上传、文本上传、分片上传、**官网爬虫附件入库**等；签名 URL 下载（`get_download_url`）同样被拒
> **整理日期**：2026-09-22

---

## 一、问题现象

任何向 OSS 写入文件的操作失败，后端日志出现：

```json
{'status': 403,
 'Code': 'AccessDenied',
 'Message': 'You have no right to access this object because of bucket acl.',
 'HostId': 'campus-resource.oss-cn-hangzhou.aliyuncs.com',
 'EC': '0003-00000001'}
```

典型表现：

- 上传接口报错 / 前端提示上传失败
- 爬虫日志：`OSS 文本上传失败` / `OSS 二进制上传失败 ... AccessDenied`，文档跳过保存
- 索引任务下载文件失败（`下载/抽取失败 ... 403 Forbidden`），文档 status 变为 `failed`

## 二、快速定位

**关键看错误码，区分两种 403：**

| 错误信息 | 含义 | 结论 |
|---|---|---|
| `SignatureDoesNotMatch` | Secret 不对 | 换正确的 `OSS_ACCESS_KEY_SECRET` 即可 |
| `InvalidAccessKeyId` | Key ID 不存在/填错 | 核对 `OSS_ACCESS_KEY_ID` |
| `AccessDenied ... because of bucket acl` | **签名有效，但该 RAM 身份对这个桶没有任何授权** | 本文讨论的情况 |

一句话判断：**能通过签名校验却被拒 → 不是密码错了，是这个账号"没被授权"访问这个桶**。

## 三、原因分析

本项目 `.env` 的 OSS 四项配置：

```ini
OSS_ACCESS_KEY_ID=LTAI5tAi****        # RAM 用户的 AccessKey
OSS_ACCESS_KEY_SECRET=******
OSS_ENDPOINT=oss-cn-hangzhou.aliyuncs.com
OSS_BUCKET_NAME=campus-resource
```

出现 bucket acl 类 403，一般是以下之一：

1. **RAM 用户没挂权限策略**——AccessKey 是某个 RAM 用户的，但该用户没有绑定任何允许 `oss:PutObject` 的策略（最常见：建了用户、拿了 key，忘了授权）
2. **桶和 key 不属于同一个阿里云账号**——桶是队友 A 账号建的，key 是队友 B 账号的，跨账号访问必须在桶上做 Bucket Policy 授权
3. **桶 ACL 近期改过**——之前是公共读写（匿名也能传），改成私有后所有未授权请求被拒

> 另外注意：`backend/config/settings.py` 中 `OSS_ENDPOINT` 的默认值是 `oss-cn-chengdu`，而本机 `.env` 指向 `oss-cn-hangzhou` 的 `campus-resource` 桶。**部署服务器与本机可能用的不是同一套桶/凭证**，排查时先确认 `.env` 到底指向哪个桶。

## 四、解决方案（按实际情况三选一）

### 方案 1：桶在自己的阿里云账号，给 RAM 用户授权

1. 登录阿里云控制台 → **RAM 访问控制** → **用户**
2. 找到 `OSS_ACCESS_KEY_ID` 对应的 RAM 用户（控制台能按 AK 查归属用户）
3. **权限管理** → 新增授权 → 勾选 `AliyunOSSFullAccess`
   （更小权限做法：自定义策略，只允许该桶的 `oss:PutObject` / `oss:GetObject`）
4. 无需改代码，1-2 分钟内生效

### 方案 2：桶是队友账号的，做跨账号授权

让**桶的主人**操作（两种任选）：

- OSS 控制台 → 对应桶 → **权限控制 → Bucket Policy** → 新增授权，把你的 RAM 用户/账号加为被授权主体，动作为读写（`oss:PutObject`/`oss:GetObject`）
- 或直接把桶主人自己账号下新建的一组 AccessKey 给你用（同时更新 `.env` 四项）

### 方案 3：直接同步部署服务器的可用配置（最省事）

部署服务器上的系统一直在正常上传，说明服务器的凭证是可用的：

1. 登录部署服务器，打开 `C:\wwwroot\campus_resource\backend\.env`
2. 把 `OSS_ACCESS_KEY_ID / OSS_ACCESS_KEY_SECRET / OSS_ENDPOINT / OSS_BUCKET_NAME` 四项复制到本机 `backend/.env`
3. 重启后端进程生效

在项目根目录跑（输出 `True` 即恢复）：

```bash
python -c "import os,sys; os.environ.setdefault('DJANGO_SETTINGS_MODULE','config.settings'); sys.path.insert(0,'backend'); import django; django.setup(); from utils.oss import oss_client; print(oss_client.upload_text('test','knowledge/website/0/_perm_test.txt'))"
```

通过后建议顺手删掉测试对象 `knowledge/website/0/_perm_test.txt`，再跑一次官网爬虫确认链路完整：

```bash

python manage.py crawl_website --dry-run --pages 30   # 先预览能发现哪些附件（不入库）
python manage.py crawl_website --pages 200            # 正文 + 附件一起爬取入库
```

## 六、附注

- **密钥安全**：AccessKey Secret 出现在终端日志/聊天记录里后，建议到 RAM 控制台为该用户新建 AccessKey 并禁用旧的（`OSS_ACCESS_KEY_SECRET` 泄露 = 别人可以完全以该身份操作你的 OSS）
- `.env` 不入 git（已在 `.gitignore`），不要把真实密钥写进任何文档
- 相关代码位置：OSS 客户端 `backend/utils/oss.py`（`upload_text` / `upload_bytes` / `get_download_url`）；爬虫 OSS 路径前缀 `knowledge/website/0/{YYYY-MM}/`；上传接口的直传写法见 `backend/apps/knowledge/views.py` 的 `FileUploadView`
